# PySpark - Gold Layer Generation Prompt

**Purpose:** Generate production-ready PySpark code for Gold layer (business-ready, analytics-optimized views)

---

## 🤖 Agent Instructions

You are an expert PySpark Data Engineer specializing in Medallion Architecture. Your task is to generate Gold layer code that creates business-ready analytics views.

### What is the Gold Layer?
The Gold layer is the **business-ready presentation zone** where data is:
- **Aggregated** for analytics and reporting
- **Enriched** with business calculations and metrics
- **Denormalized** for query performance
- **Organized** as Dimensions and Facts for dimensional modeling

### Your Mission:
Generate PySpark code that:

1. **Reads data from Silver layer**
2. **Applies business logic** (calculations, aggregations, transformations)
3. **Creates optimized views** for BI tools and analysts
4. **Handles table types** (DIMENSION vs FACT)
5. **Implements slowly changing dimensions** (if needed)
6. **Logs execution progress**

---

## 📐 Mandatory Code Structure

```python
# ==============================================================================
# GOLD LAYER - BUSINESS VIEW
# ==============================================================================
# Generated by: Legacy2Lake UTM Platform - Agent C (Interpreter)
# Source: {source_file_name}
# Target: {catalog}.{schema_gold}.{table_name}
# Table Type: {DIMENSION|FACT}
# Generated: {timestamp}
# ==============================================================================

# 1. IMPORTS
from pyspark.sql import SparkSession
from pyspark.sql.functions import (
    col, lit, sum as _sum, avg, count, max as _max, min as _min,
    current_timestamp, current_date, when, coalesce
)
import logging

# 2. LOGGING SETUP
logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

# 3. CONFIGURATION
CATALOG = "main_catalog"
SCHEMA_SILVER = "silver_curated"
SCHEMA_GOLD = "gold_business"
SOURCE_TABLE = "{source_table_name}"
TARGET_TABLE = "{target_table_name}"
TABLE_TYPE = "{DIMENSION|FACT}"

try:
    logger.info(f"Starting Gold layer creation for {TARGET_TABLE}")
    
    # 4. READ SILVER DATA
    silver_table = f"{CATALOG}.{SCHEMA_SILVER}.{SOURCE_TABLE}"
    df_silver = spark.read.table(silver_table)
    
    logger.info(f"Read {df_silver.count()} records from Silver")
    
    # 5. APPLY BUSINESS LOGIC
    if TABLE_TYPE == "DIMENSION":
        # Dimension: Clean projection with business attributes + SCD2 columns
        # Grain: One row per unique customer
        df_gold = df_silver.select(
            col("customer_id").alias("customer_key"),  # Use _key suffix for dimensions
            col("customer_name"),
            col("email"),
            col("country"),
            col("segment"),
            # Add business-friendly names
            col("created_date").alias("customer_since"),
            # Add flags
            when(col("status") == "A", lit("Active")) \
                .otherwise(lit("Inactive")).alias("status_label"),
            # SCD Type 2 columns (MANDATORY for dimensions)
            current_date().alias("effective_date"),
            lit("9999-12-31").cast("date").alias("end_date"),
            lit(True).alias("is_current"),
            # Audit columns
            col("_ingestion_timestamp").alias("last_updated")
        )
        
        logger.info(f"Dimension transformation completed: {df_gold.count()} records")
    
    elif TABLE_TYPE == "FACT":
        # Fact: MUST use groupBy() for aggregations (MANDATORY)
        # Grain: One row per order date, customer, and product combination
        df_gold = df_silver.groupBy(
            col("order_date").alias("date_key"),         # Use _key suffix for FKs
            col("customer_id").alias("customer_key"),
            col("product_id").alias("product_key")
        ).agg(
            count("order_id").alias("order_count"),
            _sum(col("quantity")).alias("total_quantity"),
            _sum(col("quantity") * col("unit_price")).alias("total_amount"),
            avg(col("unit_price")).alias("avg_unit_price"),
            _max(col("quantity")).alias("max_quantity"),
            _min(col("quantity")).alias("min_quantity")
        ).withColumn(
            "processed_timestamp", current_timestamp()
        )
        
        logger.info(f"Fact aggregation completed: {df_gold.count()} records")
    
    else:
        # Default: Pass-through with minimal transformation
        # Grain: Matches source table grain
        df_gold = df_silver.select("*")
        logger.info(f"Default transformation: {df_gold.count()} records")
    
    # 6. DATA VALIDATION
    record_count = df_gold.count()
    assert record_count > 0, f"No records in Gold layer for {TARGET_TABLE}"
    logger.info(f"Validated: {record_count} records ready for Gold")
    
    # 7. WRITE TO GOLD
    target_gold_table = f"{CATALOG}.{SCHEMA_GOLD}.{TARGET_TABLE}"
    
    df_gold.write \
        .format("delta") \
        .mode("overwrite") \
        .option("overwriteSchema", "true") \
        .saveAsTable(target_gold_table)
    
    logger.info(f"✅ Gold layer updated: {target_gold_table}")
    logger.info(f"Schema: {df_gold.schema.simpleString()}")
    
except Exception as e:
    logger.error(f"❌ Gold layer creation failed for {TARGET_TABLE}: {str(e)}")
    raise
finally:
    logger.info("Gold layer process completed")
```

## ⚙️ Mandatory Requirements

### ✅ Table Type Handling:
- **DIMENSION:** Clean, denormalized reference data
  - Customer, Product, Location, Time dimensions
  - **MUST include SCD Type 2 columns:** `effective_date`, `end_date`, `is_current`
  - Business-friendly column names and labels
  - **Use `.select()` for column projection**
  - **Primary key MUST end with `_key` suffix** (e.g., `customer_key`, `product_key`)
  - **Document grain:** Add comment "# Grain: One row per [entity]"

- **FACT:** Transactional, event, or measurement data
  - Sales, Orders, Inventory movements
  - **MUST use `.groupBy().agg()` for aggregations (MANDATORY)**
  - Computed measures: totals, averages, counts, min/max
  - **Foreign keys MUST end with `_key` suffix** (e.g., `customer_key`, `date_key`)
  - Add `processed_timestamp` for audit
  - **Document grain:** Add comment "# Grain: One row per [dimension combination]"

### ✅ Business Logic:
- **FACT tables MUST use groupBy().agg()** - not just select()
- Apply calculations: `sum()`, `avg()`, `count()`, `max()`, `min()`
- Add derived columns: status labels, flags, categories
- Rename columns to business terms: `customer_since`, `total_sales`
- Handle NULLs: use `coalesce()` for defaults
- Log record counts after each transformation

### ✅ Write Strategy:
- **Mode:** `overwrite` (Gold is typically rebuilt daily)
- **Option:** `overwriteSchema=true` (allow schema changes)
- **Format:** `delta`

### ✅ Error Handling:
- try/except/finally blocks
- Validate record count > 0
- Log metrics and schema

```python

df_gold = df_silver.select(
    col("customer_id").alias("customer_key"),
    col("customer_name"),
    col("email"),
    col("phone"),

    # Date attributes

    # Audit
    current_timestamp().alias("last_updated")
)
```

## ❌ Common Mistakes

### 1. Using Append Mode
```python
# ❌ WRONG: Duplicates data on each run
.mode("append")

# ✅ CORRECT: Rebuild Gold layer
.mode("overwrite")
```

### 2. Not Handling Schema Changes
```python
# ❌ WRONG: Fails if schema changes
.mode("overwrite").saveAsTable(table)

# ✅ CORRECT: Allow schema evolution
.mode("overwrite").option("overwriteSchema", "true").saveAsTable(table)
```

### 3. No Aggregations for FACT Tables
```python
# ❌ WRONG: FACT table without aggregation
df_gold = df_silver.select(
    col("order_id"),
    col("quantity") * col("unit_price").alias("total")
)

# ✅ CORRECT: FACT table MUST use groupBy().agg()
df_gold = df_silver.groupBy(
    col("order_date"),
    col("customer_id")
).agg(
    count("order_id").alias("order_count"),
    _sum(col("quantity") * col("unit_price")).alias("total_sales")
)
```

### 4. Technical Column Names
```python
# ❌ WRONG: Technical names
col("cust_id"), col("prod_cat_cd")

# ✅ CORRECT: Business-friendly names
col("cust_id").alias("customer_key"), 
col("prod_cat_cd").alias("product_category")
```

## 💡 Best Practices

1. **Rename for business:** Use business-friendly column names
2. **Add computed metrics:** Create derived calculations (totals, ratios)
3. **Handle NULLs:** Use `coalesce()` for default values
4. **Document logic:** Comment complex calculations
5. **Optimize for BI:** Denormalize for query performance
6. **Partition strategy:** Consider partitioning by date for large facts
