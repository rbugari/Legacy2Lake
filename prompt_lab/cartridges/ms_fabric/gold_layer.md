## 🤖 Agent Instructions

### What is the Gold Layer in MS Fabric?
The Gold layer is the **business presentation zone** in Fabric Lakehouses where:
- Data is **aggregated** for analytics and Power BI
- **Business calculations** and derived metrics
- **Denormalized** for query performance
- **V-Order optimized** for Direct Lake mode
- **Star schema** compatible (Facts and Dimensions)
- **Semantic models** can read directly from tables

### Your Mission:
Generate PySpark Notebook code that:

1. **Reads from Silver Lakehouse**
2. **Applies business logic** (calculations, aggregations)
3. **Creates Power BI-ready views**
4. **Handles DIMENSION vs FACT tables**
5. **Optimizes with V-Order** for Direct Lake
6. **Uses overwrite mode** (Gold is rebuilt)
7. **Logs execution**

## 📐 Mandatory Code Structure

```python
# ==============================================================================
# MS FABRIC - GOLD LAYER (Business/Semantic)
# ==============================================================================
# Generated by: Legacy2Lake UTM Platform - Agent C (Interpreter)
# Source Lakehouse: silver
# Target Lakehouse: gold
# Table: {table_name}
# Table Type: {DIMENSION|FACT}
# Power BI: Direct Lake Compatible
# Generated: {timestamp}
# ==============================================================================

# Cell 1: Imports
from pyspark.sql import SparkSession
from pyspark.sql.functions import (
    col, lit, sum as _sum, avg, count,
    current_timestamp, when, coalesce
)
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

# Cell 2: Configuration
LAKEHOUSE_SILVER = "silver"
LAKEHOUSE_GOLD = "gold"
SOURCE_TABLE = "{source_table}"
TARGET_TABLE = "{target_table}"
TABLE_TYPE = "{DIMENSION|FACT}"

try:
    logger.info(f"Starting Gold layer for {TARGET_TABLE}")
    
    # Cell 3: Read Silver
    silver_table = f"{LAKEHOUSE_SILVER}.{SOURCE_TABLE}"
    df_silver = spark.read.table(silver_table)
    
    logger.info(f"Read {df_silver.count()} records from Silver")
    
    # Cell 4: Apply Business Logic
    if TABLE_TYPE == "DIMENSION":
        # Dimension: Business-friendly projections
        df_gold = df_silver.select(
            col("customer_id").alias("CustomerKey"),
            col("customer_name").alias("CustomerName"),
            col("email").alias("Email"),
            col("country").alias("Country"),
            # Business labels
            when(col("status") == "A", lit("Active")) \
                .otherwise(lit("Inactive")).alias("StatusLabel"),
            # Dates
            col("registration_date").alias("CustomerSinceDate"),
            # Audit
            col("_FabricIngestTime").alias("LastUpdated")
        )
    
    elif TABLE_TYPE == "FACT":
        # Fact: Computed measures for Power BI
        df_gold = df_silver.select(
            col("order_id").alias("OrderKey"),
            col("customer_id").alias("CustomerKey"),
            col("product_id").alias("ProductKey"),
            col("order_date").alias("DateKey"),
            # Measures
            col("quantity").alias("Quantity"),
            col("unit_price").alias("UnitPrice"),
            # Computed measures
            (col("quantity") * col("unit_price")).alias("TotalAmount"),
            ((col("quantity") * col("unit_price")) * col("discount_pct")).alias("DiscountAmount"),
            # Derived metrics
            current_timestamp().alias("ProcessedTimestamp")
        )
    
    else:
        # Default: Passthrough with renaming
        df_gold = df_silver.select("*")
    
    logger.info(f"Applied {TABLE_TYPE} business logic")
    
    # Cell 5: Data Validation
    record_count = df_gold.count()
    assert record_count > 0, f"No records for Gold layer: {TARGET_TABLE}"
    logger.info(f"Validated: {record_count} records")
    
    # Cell 6: Write to Gold Lakehouse
    target_gold_table = f"{LAKEHOUSE_GOLD}.{TARGET_TABLE}"
    
    df_gold.write \
        .format("delta") \
        .mode("overwrite") \
        .option("overwriteSchema", "true") \
        .option("delta.enableChangeDataFeed", "true") \
        .saveAsTable(target_gold_table)
    
    logger.info(f"✅ Gold layer updated: {target_gold_table}")
    
    # Cell 7: Optimize for Power BI Direct Lake (CRITICAL)
    if TABLE_TYPE == "DIMENSION":
        # Optimize dimensions by primary key
        spark.sql(f"""
            OPTIMIZE {target_gold_table}
            VORDER BY (CustomerKey)
        """)
    elif TABLE_TYPE == "FACT":
        # Optimize facts by date (most common filter in Power BI)
        spark.sql(f"""
            OPTIMIZE {target_gold_table}
            VORDER BY (DateKey)
        """)
    else:
        # Default optimization
        spark.sql(f"OPTIMIZE {target_gold_table}")
    
    logger.info(f"✅ Table optimized with V-Order for Power BI Direct Lake")
    logger.info(f"✅ {record_count} records ready for semantic model")
    
except Exception as e:
    logger.error(f"❌ Gold layer failed: {str(e)}")
    raise
finally:
    logger.info("Gold layer process completed")
```

## ⚙️ Mandatory Requirements

### ✅ Table Types (Star Schema):

#### DIMENSION (Reference Data):
- Customer, Product, Date, Location
- **Column naming:** PascalCase for Power BI (CustomerKey, CustomerName)
- **V-Order by:** Primary Key
- **Size:** Typically smaller (<10M rows)
- **Power BI:** Used for filters and slicers

#### FACT (Transactional Data):
- Sales, Orders, Events
- **Foreign keys:** CustomerKey, ProductKey, DateKey
- **Measures:** TotalAmount, Quantity, etc.
- **V-Order by:** DateKey (most common filter)
- **Size:** Can be large (>100M rows)
- **Power BI:** Used for aggregations and measures

### ✅ Power BI Optimization:
- **V-Order:** MANDATORY for Direct Lake mode
- **Column names:** PascalCase (Power BI convention)
- **Data types:** Align with Power BI semantic model
- **Avoid:** Complex nested structures (flatten for Power BI)

### ✅ Write Strategy:
- **Mode:** `overwrite` (rebuild daily/hourly)
- **Options:**
  - `overwriteSchema=true` - Allow schema changes
  - `delta.enableChangeDataFeed=true` - CDC support

## 📚 Examples

### Example 1: Dimension (Customer)

```python
# Cell: Business Logic for Customer Dimension
df_gold = df_silver.select(
    col("customer_id").alias("CustomerKey"),
    col("customer_name").alias("CustomerName"),
    col("email").alias("Email"),
    col("country").alias("Country"),
    # Business segments
    when(col("total_purchases") > 10000, "VIP")

        .otherwise("Standard").alias("CustomerSegment"),
    # Status label
    when(col("status") == "A", "Active")
        .otherwise("Inactive").alias("Status"),

)

df_gold.write.format("delta").mode("overwrite").saveAsTable("gold.DimCustomer")

```

### Example 2: Fact (Sales)

```python
# Cell: Business Logic for Sales Fact
df_gold = df_silver.select(
    col("order_id").alias("OrderKey"),
    col("line_number").alias("LineNumber"),
    # Foreign keys
    col("customer_id").alias("CustomerKey"),
    col("product_id").alias("ProductKey"),
    col("order_date").alias("DateKey"),
    # Measures
    col("quantity").alias("Quantity"),
    col("unit_price").alias("UnitPrice"),
    # Computed measures

    (col("quantity") * col("unit_price") * col("discount_pct")).alias("Discount"),

    ((col("unit_price") - col("cost")) * col("quantity")).alias("TotalProfit")
)

# Write to Gold
df_gold.write.format("delta").mode("overwrite").saveAsTable("gold.FactSales")

# Optimize for Power BI (by date - most common filter)
spark.sql("OPTIMIZE gold.FactSales VORDER BY (DateKey)")
```

## ❌ Common Mistakes

### 1. Not Using V-Order
```python
# ❌ WRONG: Poor Power BI performance
df.write.format("delta").saveAsTable("gold.table")

# ✅ CORRECT: V-Order for Direct Lake
df.write.format("delta").saveAsTable("gold.table")
spark.sql("OPTIMIZE gold.table VORDER BY (KeyColumn)")
```

### 2. snake_case Column Names
```python
# ❌ WRONG: Not Power BI friendly
col("customer_id"), col("total_amount")

# ✅ CORRECT: PascalCase for Power BI
col("customer_id").alias("CustomerKey"),
col("total_amount").alias("TotalAmount")
```

### 3. Wrong V-Order Column
```python
# ❌ WRONG: V-Order by rarely-filtered column
OPTIMIZE gold.FactSales VORDER BY (OrderKey)

# ✅ CORRECT: V-Order by most common filter
OPTIMIZE gold.FactSales VORDER BY (DateKey)
```

## 💡 Best Practices

1. **V-Order by usage:** DateKey for facts, PK for dimensions
2. **PascalCase naming:** Match Power BI semantic model convention
3. **Flatten structures:** Avoid nested columns for Power BI compatibility
4. **Computed measures:** Pre-calculate common metrics
5. **Date dimensions:** Create separate DateKey dimension table
6. **Direct Lake mode:** Test with Power BI semantic models
7. **Refresh strategy:** Rebuild Gold tables on schedule (hourly/daily)

### Power BI Direct Lake Benefits:
- **No import:** Power BI reads directly from Lakehouse
- **Real-time:** Changes reflect immediately
- **Large datasets:** Handle billions of rows
- **V-Order:** Columnar compression optimized for queries
- **Cost-effective:** No data duplication
