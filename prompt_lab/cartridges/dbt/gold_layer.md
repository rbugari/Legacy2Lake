# dbt - Gold Layer Generation Prompt

**Purpose:** Generate production-ready dbt SQL models for Gold/Marts layer (business-ready analytics views)

---

## 🤖 Agent Instructions

You are an expert dbt Analytics Engineer. Generate Gold layer (Marts) models that create business-ready views for BI tools and analysts.

### What is the Gold Layer in dbt?
The Gold layer is the **Marts layer** where:
- Data is **aggregated** for analytics
- **Business calculations** are applied
- **Denormalized** for query performance
- **Fact and Dimension** models for star schema
- Materialized as **tables** or **views**

### Your Mission:
Generate dbt SQL models that:

1. **Read from Silver models** using `{{ ref() }}`
2. **Apply business logic** (calculations, aggregations, transformations)
3. **Create dimension or fact tables**
4. **Use business-friendly column names**
5. **Materialize appropriately** (table for facts, view for dimensions)
6. **Document for end users**

```sql

{# GOLD LAYER (MARTS / BUSINESS READY)                                        #}
{# =========================================================================== #}
{# Generated by: Legacy2Lake UTM Platform - Agent C (Interpreter)            #}
{# Source: silver.int_{{ table_name }}                                       #}
{# Target: gold.fct_{{ table_name }} or dim_{{ table_name }}                 #}
{# Table Type: {{ FACT | DIMENSION }}                                         #}
{# Generated: {{ timestamp }}                                                 #}
{# =========================================================================== #}

-- dbt config: Materialize as table in gold schema
{{
  config(
    materialized='table',
    schema='gold'
  )
}}

-- Read from Silver intermediate model
with silver as (
    select * from {{ ref('int_{{ table_name }}') }}
),

-- Apply business logic
business_logic as (
    select
        -- Primary/Foreign keys
        customer_id as customer_key,
        
        -- Attributes with business-friendly names
        customer_name,
        email as customer_email,
        country as customer_country,
        
        -- Computed metrics (for FACT tables)
        quantity,
        unit_price,
        quantity * unit_price as total_amount,
        
        -- Business labels
        case 
            when status = 'A' then 'Active'
            when status = 'I' then 'Inactive'
            else 'Unknown'
        end as customer_status_label,
        
        -- Audit
        _ingested_at as last_updated_timestamp
        
    from silver
)

select * from business_logic
```

- **Materialization:** `table` (or `view` for small dimensions)

### ✅ Table Types:

#### DIMENSION (Reference Data):
- Customer, Product, Date, Location
- Business-friendly names
- Status labels and flags
- Can be materialized as `view` if small

#### FACT (Transactional Data):
- Sales, Orders, Events
- Foreign keys to dimensions
- Computed measures
- Always materialized as `table`

### ✅ Business Logic:
- Rename columns to business-friendly names
- Add computed metrics (totals, ratios, percentages)
- Create status labels (Active/Inactive)
- Handle NULLs with COALESCE or CASE

### ✅ Column Naming:
- Use business terminology
- Suffix keys: `_key`, `_id`
- Descriptive names: `total_sales`, `customer_lifetime_value`

## 📚 Examples

### Example 1: Dimension (Customer)

```sql
-- models/gold/dim_customers.sql

{{
  config(
    materialized='table',
    schema='gold'
  )
}}

with silver as (
    select * from {{ ref('int_customers') }}
),

customer_dimension as (
    select
        -- Dimension key
        customer_id as customer_key,
        
        -- Attributes
        customer_name,
        email as customer_email,
        phone as customer_phone,
        country as customer_country,
        
        -- Business labels
        case 
            when customer_status = 'A' then 'Active'
            when customer_status = 'I' then 'Inactive'
            else 'Unknown'
        end as status_label,
        
        -- Segment classification
        case 
            when total_purchases > 10000 then 'VIP'
            when total_purchases > 1000 then 'Premium'
            else 'Standard'
        end as customer_segment,
        
        -- Dates
        registration_date as customer_since_date,
        
        -- Audit
        _ingested_at as last_updated
        
    from silver
)

select * from customer_dimension
```

### Example 2: Fact (Sales)

```sql
-- models/gold/fct_sales.sql

{{
  config(
    materialized='table',
    schema='gold'
  )
}}

with silver as (
    select * from {{ ref('int_orders') }}
),

sales_fact as (
    select
        -- Fact grain: order line level
        order_id as order_key,
        line_number,
        
        -- Foreign keys to dimensions
        customer_id as customer_key,
        product_id as product_key,
        order_date as date_key,
        
        -- Measures
        quantity,
        unit_price,
        
        -- Computed measures
        quantity * unit_price as gross_sales,
        quantity * unit_price * discount_percentage as discount_amount,
        quantity * unit_price * (1 - discount_percentage) as net_sales,
        unit_price - cost as profit_per_unit,
        (unit_price - cost) * quantity as total_profit,
        
        -- Ratios
        (unit_price - cost) / nullif(unit_price, 0) as profit_margin,
        
        -- Flags
        case when discount_percentage > 0 then true else false end as is_discounted,
        
        -- Audit
        _ingested_at as processed_timestamp
        
    from silver
)

select * from sales_fact
```

### Example 3: Aggregated Fact (Daily Sales Summary)

```sql
-- models/gold/fct_daily_sales.sql

{{
  config(
    materialized='table',
    schema='gold'
  )
}}

with sales as (
    select * from {{ ref('fct_sales') }}
),

daily_summary as (
    select
        date_key,
        customer_key,
        
        -- Aggregated measures
        count(distinct order_key) as total_orders,
        sum(quantity) as total_quantity,
        sum(net_sales) as total_net_sales,
        sum(total_profit) as total_profit,
        avg(profit_margin) as avg_profit_margin,
        
        -- Computed ratios
        sum(total_profit) / nullif(sum(net_sales), 0) as profit_margin_pct,
        
        -- Current timestamp
        current_timestamp() as calculated_at
        
    from sales
    group by date_key, customer_key
)

select * from daily_summary
```

## ❌ Common Mistakes

### 1. Technical Column Names
```sql
-- ❌ WRONG
cust_id, prod_cat_cd, amt

-- ✅ CORRECT
customer_key, product_category, total_amount
```

### 2. No Business Logic
```sql
-- ❌ WRONG: Just copying Silver
select * from {{ ref('int_customers') }}

-- ✅ CORRECT: Add business value
select
    customer_id as customer_key,
    case when status = 'A' then 'Active' else 'Inactive' end as status_label,
    revenue * 0.2 as estimated_profit
from {{ ref('int_customers') }}
```

### 3. Not Handling NULLs in Calculations
```sql
-- ❌ WRONG: Division by zero
net_sales / gross_sales as margin

-- ✅ CORRECT: Use NULLIF
net_sales / nullif(gross_sales, 0) as margin
```

## 💡 Best Practices

1. **Prefix models:** `fct_` for facts, `dim_` for dimensions
2. **Business-friendly names:** Match business terminology
3. **Computed metrics:** Add all useful calculations
4. **Handle NULLs:** Use COALESCE, NULLIF, CASE
5. **Document:** Add descriptions to schema.yml
6. **Test:** Add dbt tests for data quality
7. **Optimize:** Consider incremental for large fact tables
