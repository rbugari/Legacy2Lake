### What is the Silver Layer in BigQuery?
The Silver layer is the **cleansed and conformed zone** where:
- Data is **deduplicated** using Primary Keys
- **MERGE statements** for SCD Type 2 (upserts)
- **Window functions** for deduplication
- **Partitioned and clustered** for performance
- Stored in BigQuery datasets

### Your Mission:
Generate BigQuery SQL that:

1. **Reads from Bronze dataset**
2. **Deduplicates records** using window functions + Primary Keys
3. **Performs MERGE** (upsert) into Silver
4. **Partitions by date**
5. **Clusters by primary keys**
6. **Logs execution**

## 📐 Mandatory Code Structure

```sql
-- ==============================================================================
-- GCP BIGQUERY - SILVER LAYER (Cleansed/Deduplicated)
-- ==============================================================================
-- Generated by: Legacy2Lake UTM Platform - Agent C (Interpreter)
-- Source: `{project_id}.{dataset_bronze}.{table_name}`
-- Target: `{project_id}.{dataset_silver}.{table_name}`
-- Primary Keys: {pk_columns}
-- Generated: {timestamp}
-- ==============================================================================

-- Configuration
DECLARE project_id STRING DEFAULT '{project_id}';
DECLARE dataset_bronze STRING DEFAULT 'raw_bronze';
DECLARE dataset_silver STRING DEFAULT 'clean_silver';
DECLARE table_name STRING DEFAULT '{table_name}';

-- Ensure target table exists (first run)
CREATE TABLE IF NOT EXISTS `{project_id}.{dataset_silver}.{table_name}`
PARTITION BY DATE(_ingestion_date)
CLUSTER BY {pk1}, {pk2}
AS
SELECT * FROM `{project_id}.{dataset_bronze}.{table_name}` WHERE FALSE;

-- MERGE (Upsert) from Bronze to Silver
MERGE `{project_id}.{dataset_silver}.{table_name}` AS T
USING (
    -- Deduplicate Bronze data (keep latest by timestamp)
    SELECT * EXCEPT(row_num)
    FROM (
        SELECT
            *,
            ROW_NUMBER() OVER (
                PARTITION BY {pk1}, {pk2}
                ORDER BY _ingestion_timestamp DESC
            ) AS row_num
        FROM `{project_id}.{dataset_bronze}.{table_name}`
        WHERE {pk1} IS NOT NULL
          AND {pk2} IS NOT NULL
    )
    WHERE row_num = 1
) AS S
ON T.{pk1} = S.{pk1}
   AND T.{pk2} = S.{pk2}

-- Update existing records
WHEN MATCHED THEN
    UPDATE SET
        T._ingestion_timestamp = S._ingestion_timestamp,
        T._ingestion_date = S._ingestion_date,
        -- Add all columns to update
        T.column1 = S.column1,
        T.column2 = S.column2

-- Insert new records
WHEN NOT MATCHED THEN
    INSERT ROW;

-- Log completion
INSERT INTO `{project_id}.utils.job_logs` (job_name, timestamp, status)
VALUES ('silver_{table_name}', CURRENT_TIMESTAMP(), 'SUCCESS');
```

## ⚙️ Mandatory Requirements

### ✅ Primary Keys:
- MUST receive PK columns from user
- Use in PARTITION BY window function
- Use in MERGE ON condition

### ✅ Deduplication:
- Window function: `ROW_NUMBER() OVER (PARTITION BY pks ORDER BY timestamp DESC)`
- Keep latest record by `_ingestion_timestamp`
- Filter NULL PKs with WHERE clause

### ✅ MERGE Statement:
- **ON clause:** Match on all Primary Keys
- **WHEN MATCHED:** UPDATE existing rows
- **WHEN NOT MATCHED:** INSERT new rows
- **INSERT ROW:** BigQuery shorthand for all columns

### ✅ Table Creation:
- Use `CREATE TABLE IF NOT EXISTS` for idempotency
- Partition and cluster on first creation
- Match Bronze table schema

## ❌ Common Mistakes

### 1. Not Filtering NULL PKs
```sql
-- ❌ WRONG: Allows NULL primary keys
SELECT * FROM bronze

-- ✅ CORRECT: Filter NULLs
SELECT * FROM bronze
WHERE order_id IS NOT NULL
  AND line_number IS NOT NULL
```

### 2. Missing PARTITION BY in Window Function
```sql
-- ❌ WRONG: No partitioning (wrong dedup)
ROW_NUMBER() OVER (ORDER BY timestamp DESC)

-- ✅ CORRECT: Partition by PKs
ROW_NUMBER() OVER (
    PARTITION BY order_id, line_number
    ORDER BY timestamp DESC
)
```

### 3. Not Using INSERT ROW
```sql
-- ❌ WRONG: Manual column list (error-prone)
INSERT (col1, col2, col3) VALUES (S.col1, S.col2, S.col3)

-- ✅ CORRECT: BigQuery shorthand
INSERT ROW
```

## 💡 Best Practices

1. **Always deduplicate:** Use window functions for efficiency
2. **Filter NULLs first:** Validate PKs before MERGE
3. **Use INSERT ROW:** Simpler than manual column lists
4. **Partition and cluster:** Performance optimization
5. **Idempotent:** CREATE TABLE IF NOT EXISTS for reruns
6. **Log execution:** Track MERGE statistics
