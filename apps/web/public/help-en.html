🎯 What is Legacy2Lake?

Legacy2Lake is an automated migration platform that uses Artificial Intelligence to transform legacy systems (SSIS, SQL Server, Oracle, etc.) into modern Data Lake architectures (PySpark, Snowflake, Databricks, BigQuery).

✨ Key Features

  • Automated Migration: Specialized AI agents generate production-ready code.
  • Multi-Tenancy: Support for multiple organizations with complete isolation.
  • Cloud-Native: Storage on Cloudflare R2, metadata on Supabase.
  • Complete Traceability: Every decision is documented and audited.
  • Professional Reports: Executive PDFs for Triage and Handover.

🤖 The 7 AI Agents

  • Agent A (The Analyst): Analyzes legacy code and generates technical manifests.
  • Agent S (The Scout): Forensic detective that identifies gaps and migration risks.
  • Agent B (The Architect): Designs execution topology and dependencies.
  • Agent C (The Developer): Generates optimized PySpark/SQL code.
  • Agent F (The Critic): Audits and validates generated code against standards.
  • Agent G (The Governor): Generates governance documentation and runbooks.
  • The Librarian: Extracts schema and table metadata for context.

⚙️ How does the process work?

Legacy2Lake follows a 6-stage sequential workflow, each with a specific purpose and automatic validations. The system ensures you cannot advance to the next stage without completing the current one.

📊 Workflow

  1. Discovery: Upload your legacy files to the system.
  2. Triage: AI analyzes and classifies assets.
  3. Drafting: Migration code is generated.
  4. Refinement: Code is optimized and self-corrected.
  5. Certification: Compliance is validated and documentation generated.
  6. Handover: Download final code and deploy.

🔒 Governance and Control

The system implements state locks to ensure integrity:

  • You cannot modify assets while the project is in DRAFTING mode.
  • You must "Approve Triage" before generating code.
  • PDF reports are generated only when complete data is available.

📋 The 6 Process Stages

1
🔍 Discovery
Initial loading phase where you upload your legacy files (SSIS packages, SQL scripts, etc.) to the system.
🎬 User Actions
  • Create a new project
  • Configure source and target technology
  • Upload legacy files (drag & drop)
  • View inventory of loaded files
  • Advance to Triage when ready
2
🎯 Triage
AI analyzes your files, detects technologies, identifies forensic gaps, and classifies assets as CORE, SUPPORT, or IGNORED.
🎬 User Actions
  • Execute "Run Triage" (Agent A + Agent S)
  • Review dependency graph
  • Verify asset classification
  • Upload additional support files (README, schemas)
  • Download Triage PDF Report
  • Approve Triage to unlock Drafting
3
✍️ Drafting
Agent C (Developer) generates PySpark/SQL code for each CORE asset. Code is automatically saved to storage.
🎬 User Actions
  • Configure migration limit (batch size)
  • Execute "Run Migration"
  • Monitor real-time logs
  • View generated files (.py, .sql)
  • Review operational metadata (frequency, PII, etc.)
4
🔧 Refinement
Agent F (Critic) audits generated code, detects standard violations, and applies automatic optimizations.
🎬 User Actions
  • Review audit reports (_audit.json)
  • View compliance scores (0-100)
  • Apply suggested corrections
  • Re-run refinement if necessary
5
📜 Certification
Agent G (Governor) generates governance documentation, technical runbooks, and compliance certificates.
🎬 User Actions
  • Review operation runbook
  • Verify compliance certificate
  • Validate technical documentation
  • Approve for Handover
6
🎁 Handover
Final phase where you download all generated code, documentation, and manifests for production deployment.
🎬 User Actions
  • Download Final PDF Report
  • Download ZIP with all code
  • Review MANIFEST.json
  • Deploy to your environment (Databricks, Snowflake, etc.)

🎨 Customization and Configuration

🔧 Project Configuration

Each project can be customized at multiple levels:

1. Supported Technologies

Sources:
  • SSIS (SQL Server Integration Services)
  • SQL Server (T-SQL)
  • Oracle (PL/SQL)
  • MySQL
  • Informatica PowerCenter
  • IBM DataStage
Targets:
  • PySpark (Databricks, EMR, Synapse)
  • Snowflake (Snowpark Python)
  • BigQuery (SQL + Python UDFs)
  • Azure Synapse Analytics

2. Operational Metadata

For each asset you can configure:

  • Frequency: DAILY, WEEKLY, MONTHLY, HOURLY
  • Load Strategy: FULL_OVERWRITE, INCREMENTAL, SCD_TYPE2
  • Criticality: P0 (Critical), P1 (High), P2 (Medium), P3 (Low)
  • PII: Mark if it contains personal data
  • Masking Rule: HASH, ENCRYPT, REDACT, TOKENIZE
  • Business Entity: Logical domain name
  • Target Name: Override table/file name

3. Agent Configuration (Tenant Console)

From the Tenant Console (Settings) you can:

  • Agent Matrix: Assign specific LLM models to each agent (GPT-4, Claude, Gemini, etc.)
  • Provider Vault: Configure credentials for Azure OpenAI, OpenAI, Anthropic, Google AI, OpenRouter
  • System Catalog: Customize dialect instructions for each technology
  • Prompts: Edit system prompts for each agent

⚠️ Important

Changes to agent configuration affect all tenant projects. Make sure to test on a test project before applying changes to production.

❓ Frequently Asked Questions

Can I modify assets after approving Triage?

No. Once you approve Triage, the project enters DRAFTING mode and the asset inventory is locked. This ensures code generation process integrity. If you need to make changes, you must "Unlock Triage" first.

What happens if Triage detects different technologies than configured?

The system will show an alert suggesting you update the project configuration. You can accept the suggestion or keep your original configuration. Agent S always documents these discrepancies in the report.

Can I pause a migration in progress?

Yes. Migrations run asynchronously and you can close the browser. Logs are persisted in the database and you can resume them at any time. However, you cannot start a new migration while one is in progress.

How does the migration limit work?

The "Migration Limit" lets you control how many assets are processed in each execution. This is useful for:

  • Initial testing (e.g., process only 5 packages)
  • LLM cost control
  • Incremental migrations

If you set the limit to 0, all CORE assets will be processed.

What is "Support Intelligence"?

It's tribal knowledge automatically extracted from support files you upload during Triage. The system detects patterns like:

  • Schema definitions (CREATE TABLE, ALTER TABLE)
  • Volumetric data (records, table sizes)
  • Business rules documented in README

This intelligence is injected into Agent C and Agent F prompts so generated code respects your business specifications.

Can I use my own LLM models?

Yes. From the Tenant Console you can configure:

  • Azure OpenAI (GPT-4, GPT-4 Turbo, GPT-3.5)
  • OpenAI (GPT-4, GPT-4o, o1-preview)
  • Anthropic (Claude 3.5 Sonnet, Claude 3 Opus)
  • Google AI (Gemini Pro, Gemini Ultra)
  • OpenRouter (Any model available on OpenRouter)

Each agent can use a different model based on your needs and budget.

How is the compliance "Score" calculated?

Agent F (The Critic) evaluates generated code against multiple dimensions:

  • Code standards adherence (PEP8, SQL best practices)
  • Applied optimizations (partitioning, clustering, caching)
  • Error handling and logging
  • Security (PII masking, SQL injection prevention)
  • Inline documentation

Score ranges from 0 to 100. Code with score below 70 is marked as REJECTED and requires correction.

What format are the generated files?

Depending on target technology:

  • PySpark: .py (executable notebooks)
  • Snowflake: .py (Snowpark) + .sql (DDL)
  • BigQuery: .sql (queries) + .py (UDFs)

Additionally, each asset generates a _audit.json with the compliance report.
