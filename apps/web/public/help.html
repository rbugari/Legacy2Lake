Ayuda del producto

Legacy2Lake es una plataforma para entender, ordenar, generar, revisar y entregar migraciones complejas. No esta pensada como un boton de "migrar todo", sino como una forma de reducir incertidumbre y acelerar trabajo util.

Idea central: el valor del producto esta en combinar analisis, generacion, revision y trazabilidad. La plataforma ayuda a tomar mejores decisiones; no reemplaza el criterio del equipo.

Que Es Y Por Que Existe

El producto existe para ayudar en migraciones donde hay codigo legacy, poca documentacion, dependencias dificiles de leer y decisiones que normalmente consumen mucho tiempo humano.

  • ayuda a entender que hay en un repo o paquete legacy
  • ayuda a clasificar que importa y que no
  • genera una base util para revision
  • deja evidencia y artefactos de entrega

Flujo De Trabajo

El workspace trabaja por fases. Cada fase tiene un overview como punto de entrada. Ese overview es el home operativo de la fase: te orienta, te da la accion principal y te deja ir a vistas mas especificas sin perder el hilo.

FasePara que sirvePregunta principal
Discoveryentender el material de entradaQue trajimos y que tan interpretable es?
Triageclasificar y priorizarQue vale la pena migrar y como?
Draftinggenerar una base funcionalPodemos producir un primer target util?
Refinementmejorar y validarPodemos dejarlo mas solido?
Governanceauditar y documentarQue riesgos y evidencia deja la solucion?
Handoverempaquetar y entregarQue se entrega finalmente?
Navegacion actual: el sistema ya no arrastra subsecciones arbitrarias entre fases. Recuerda tu ultimo punto util dentro de la misma fase, pero una fase nueva arranca en un punto coherente.

Que Y Por Que De Cada Fase

0

Discovery

Existe para reducir incertidumbre. Antes de generar, hay que entender activos, tecnologias, ruido y huecos de contexto.

1

Triage

Existe para convertir inventario en decision. Clasifica activos y prepara una base mas segura para generar.

2

Drafting

Existe para producir un primer target util. El objetivo es una base revisable, no una optimizacion final.

3

Refinement

Existe para mejorar lo generado y reducir deuda evidente antes de auditar o entregar.

4

Governance

Existe para transformar resultados tecnicos en evidencia auditable, findings y runbook.

5

Handover

Existe para convertir el resultado del proyecto en una entrega real para otro equipo o entorno.

Como Usar Las Vistas

Overview

Es el mejor punto de entrada de cada fase. Si no sabes por donde empezar, empieza ahi.

Logs

Usalos cuando una fase esta corriendo, tarda demasiado o produce algo que no entiendes.

Grid, Graph, Files, Comparison

Son vistas de trabajo, no decoracion. Sirven para revisar decisiones, explorar dependencias y validar salidas antes de avanzar.

Importante: acciones como Run Pipeline o Run Refinement son transitorias. Por eso ya no quedan como landing persistente.

Como Sacarle Mejor Valor

  • no corras Drafting sobre un Triage mal revisado
  • usa Discovery y Triage para bajar ruido antes de generar
  • si el proyecto tiene reglas de negocio importantes, anadelas como contexto
  • usa Governance para entender riesgos, no solo para "aprobar"
  • si algo sale raro, vuelve a la fase correcta en vez de parchear todo al final

Limites Del Sistema

  • no toda logica de negocio puede inferirse automaticamente
  • no todo output generado esta listo para produccion sin revision
  • el modo direct busca fidelidad base, no rediseno completo
  • hallazgos de PII, SCD2 o gobierno pueden ser deudas reales del caso
Regla practica: usa la plataforma para tomar mejores decisiones y acelerar entregables, no para apagar el pensamiento critico del equipo.
