🎯 ¿Qué es Legacy2Lake?

Legacy2Lake es una plataforma de migración automatizada que utiliza Inteligencia Artificial para transformar sistemas legacy (SSIS, SQL Server, Oracle, etc.) en arquitecturas modernas de Data Lake (PySpark, Snowflake, Databricks, BigQuery).

✨ Características Principales

  • Migración Automatizada: Agentes de IA especializados generan código de producción.
  • Multi-Tenancy: Soporte para múltiples organizaciones con aislamiento completo.
  • Cloud-Native: Almacenamiento en Cloudflare R2, metadatos en Supabase.
  • Trazabilidad Completa: Cada decisión queda documentada y auditada.
  • Reportes Profesionales: PDFs ejecutivos para Triage y Handover.

🤖 Los 7 Agentes de IA

  • Agent A (The Analyst): Analiza el código legacy y genera manifiestos técnicos.
  • Agent S (The Scout): Detective forense que identifica gaps y riesgos de migración.
  • Agent B (The Architect): Diseña la topología de ejecución y dependencias.
  • Agent C (The Developer): Genera código PySpark/SQL optimizado.
  • Agent F (The Critic): Audita y valida el código generado contra estándares.
  • Agent G (The Governor): Genera documentación de gobernanza y runbooks.
  • The Librarian: Extrae metadatos de esquemas y tablas para contexto.

⚙️ ¿Cómo funciona el proceso?

Legacy2Lake sigue un flujo de trabajo de 6 etapas secuenciales, cada una con un propósito específico y validaciones automáticas. El sistema garantiza que no puedes avanzar a la siguiente etapa sin completar la actual.

📊 Flujo de Trabajo

  1. Discovery: Subes tus archivos legacy al sistema.
  2. Triage: La IA analiza y clasifica los activos.
  3. Drafting: Se genera el código de migración.
  4. Refinement: El código se optimiza y autocorrige.
  5. Certification: Se valida el cumplimiento y se genera documentación.
  6. Handover: Descarga del código final y despliegue.

🔒 Gobernanza y Control

El sistema implementa bloqueos de estado para garantizar la integridad:

  • No puedes modificar activos mientras el proyecto está en DRAFTING.
  • Debes "Aprobar Triage" antes de generar código.
  • Los reportes PDF se generan solo cuando hay datos completos.

📋 Las 6 Etapas del Proceso

1
🔍 Discovery
Fase de carga inicial donde subes tus archivos legacy (SSIS packages, SQL scripts, etc.) al sistema.
🎬 Acciones del Usuario
  • Crear un nuevo proyecto
  • Configurar tecnología origen y destino
  • Subir archivos legacy (drag & drop)
  • Ver inventario de archivos cargados
  • Avanzar a Triage cuando estés listo
2
🎯 Triage
La IA analiza tus archivos, detecta tecnologías, identifica gaps forenses y clasifica activos en CORE, SUPPORT o IGNORED.
🎬 Acciones del Usuario
  • Ejecutar "Run Triage" (Agent A + Agent S)
  • Revisar el grafo de dependencias
  • Verificar clasificación de activos
  • Subir archivos de soporte adicionales (README, schemas)
  • Descargar Reporte PDF de Triage
  • Aprobar Triage para desbloquear Drafting
3
✍️ Drafting
Agent C (Developer) genera código PySpark/SQL para cada activo CORE. El código se guarda automáticamente en el storage.
🎬 Acciones del Usuario
  • Configurar límite de migración (batch size)
  • Ejecutar "Run Migration"
  • Monitorear logs en tiempo real
  • Ver archivos generados (.py, .sql)
  • Revisar metadatos operacionales (frecuencia, PII, etc.)
4
🔧 Refinement
Agent F (Critic) audita el código generado, detecta violaciones de estándares y aplica optimizaciones automáticas.
🎬 Acciones del Usuario
  • Revisar reportes de auditoría (_audit.json)
  • Ver scores de cumplimiento (0-100)
  • Aplicar correcciones sugeridas
  • Re-ejecutar refinamiento si es necesario
5
📜 Certification
Agent G (Governor) genera documentación de gobernanza, runbooks técnicos y certificados de cumplimiento.
🎬 Acciones del Usuario
  • Revisar runbook de operación
  • Verificar certificado de cumplimiento
  • Validar documentación técnica
  • Aprobar para Handover
6
🎁 Handover
Fase final donde descargas todo el código generado, documentación y manifiestos para despliegue en producción.
🎬 Acciones del Usuario
  • Descargar Reporte PDF Final
  • Descargar ZIP con todo el código
  • Revisar MANIFEST.json
  • Desplegar en tu entorno (Databricks, Snowflake, etc.)

🎨 Personalización y Configuración

🔧 Configuración de Proyecto

Cada proyecto puede personalizarse en múltiples niveles:

1. Tecnologías Soportadas

Orígenes:
  • SSIS (SQL Server Integration Services)
  • SQL Server (T-SQL)
  • Oracle (PL/SQL)
  • MySQL
  • Informatica PowerCenter
  • IBM DataStage
Destinos:
  • PySpark (Databricks, EMR, Synapse)
  • Snowflake (Snowpark Python)
  • BigQuery (SQL + Python UDFs)
  • Azure Synapse Analytics

2. Metadatos Operacionales

Para cada activo puedes configurar:

  • Frecuencia: DAILY, WEEKLY, MONTHLY, HOURLY
  • Estrategia de Carga: FULL_OVERWRITE, INCREMENTAL, SCD_TYPE2
  • Criticidad: P0 (Crítico), P1 (Alto), P2 (Medio), P3 (Bajo)
  • PII: Marcar si contiene datos personales
  • Regla de Enmascaramiento: HASH, ENCRYPT, REDACT, TOKENIZE
  • Entidad de Negocio: Nombre lógico del dominio
  • Nombre de Destino: Sobrescribir nombre de tabla/archivo

3. Configuración de Agentes (Tenant Console)

Desde el Tenant Console (Settings) puedes:

  • Agent Matrix: Asignar modelos LLM específicos a cada agente (GPT-4, Claude, Gemini, etc.)
  • Provider Vault: Configurar credenciales de Azure OpenAI, OpenAI, Anthropic, Google AI
  • System Catalog: Personalizar instrucciones de dialecto para cada tecnología
  • Prompts: Editar los prompts de sistema de cada agente

⚠️ Importante

Los cambios en la configuración de agentes afectan a todos los proyectos del tenant. Asegúrate de probar en un proyecto de prueba antes de aplicar cambios en producción.

📊 Sistema de Reportes

📄 Reporte de Triage (PDF)

Generado al finalizar la etapa de Triage, incluye:

  • Executive Summary: Resumen de activos, tecnologías detectadas y riesgos
  • Forensic Assessment: Gaps críticos detectados por Agent S
  • Support Intelligence: Esquemas y volúmenes extraídos de archivos de soporte
  • Asset Inventory: Listado completo de archivos con clasificación
  • Dependency Graph: Visualización de relaciones entre activos

📄 Reporte Final (PDF)

Generado en la etapa de Handover, incluye:

  • Project Overview: Resumen ejecutivo del proyecto
  • Analytical Integrity: Tabla de resolución de gaps forenses
  • Support Intelligence Context: Contexto tribal aplicado
  • Generated Artifacts: Listado de archivos generados
  • Deployment Guide: Instrucciones de despliegue
  • Compliance Certification: Certificado de cumplimiento

✨ Características de los Reportes

  • Generación automática en formato PDF profesional
  • Marca de agua con logo del tenant
  • Tablas interactivas con métricas clave
  • Gráficos de progreso y distribución
  • Descarga directa desde la UI

❓ Preguntas Frecuentes

¿Puedo modificar activos después de aprobar Triage?

No. Una vez que apruebas Triage, el proyecto entra en modo DRAFTING y el inventario de activos queda bloqueado. Esto garantiza la integridad del proceso de generación de código. Si necesitas hacer cambios, debes "Desbloquear Triage" primero.

¿Qué pasa si el Triage detecta tecnologías diferentes a las configuradas?

El sistema te mostrará una alerta sugiriendo actualizar la configuración del proyecto. Puedes aceptar la sugerencia o mantener tu configuración original. Agent S siempre documenta estas discrepancias en el reporte.

¿Puedo pausar una migración en curso?

Sí. Las migraciones se ejecutan de forma asíncrona y puedes cerrar el navegador. Los logs se persisten en la base de datos y puedes retomarlos en cualquier momento. Sin embargo, no puedes iniciar una nueva migración mientras una esté en curso.

¿Cómo funciona el límite de migración?

El "Migration Limit" te permite controlar cuántos activos se procesan en cada ejecución. Esto es útil para:

  • Pruebas iniciales (ej: procesar solo 5 paquetes)
  • Control de costos de LLM
  • Migraciones incrementales

Si estableces el límite en 0, se procesarán todos los activos CORE.

¿Qué es la "Support Intelligence"?

Es el conocimiento tribal extraído automáticamente de archivos de soporte que subes durante Triage. El sistema detecta patrones como:

  • Definiciones de esquemas (CREATE TABLE, ALTER TABLE)
  • Datos volumétricos (registros, tamaños de tablas)
  • Reglas de negocio documentadas en README

Esta inteligencia se inyecta en los prompts de Agent C y Agent F para que el código generado respete tus especificaciones de negocio.

¿Puedo usar mis propios modelos LLM?

Sí. Desde el Tenant Console puedes configurar:

  • Azure OpenAI (GPT-4, GPT-4 Turbo, GPT-3.5)
  • OpenAI (GPT-4, GPT-4o, o1-preview)
  • Anthropic (Claude 3.5 Sonnet, Claude 3 Opus)
  • Google AI (Gemini Pro, Gemini Ultra)

Cada agente puede usar un modelo diferente según tus necesidades y presupuesto.

¿Cómo se calcula el "Score" de cumplimiento?

Agent F (The Critic) evalúa el código generado contra múltiples dimensiones:

  • Adherencia a estándares de código (PEP8, SQL best practices)
  • Optimizaciones aplicadas (partitioning, clustering, caching)
  • Manejo de errores y logging
  • Seguridad (PII masking, SQL injection prevention)
  • Documentación inline

El score va de 0 a 100. Códigos con score inferior a 70 se marcan como REJECTED y requieren corrección.

¿Qué formato tienen los archivos generados?

Dependiendo de la tecnología de destino:

  • PySpark: .py (notebooks ejecutables)
  • Snowflake: .py (Snowpark) + .sql (DDL)
  • BigQuery: .sql (queries) + .py (UDFs)

Además, cada activo genera un _audit.json con el reporte de cumplimiento.
