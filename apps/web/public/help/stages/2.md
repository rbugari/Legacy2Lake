# ⚡ Drafting Phase

> **Stage 2 of 5** · Automated 1:1 code generation from your legacy objects.

---

## 🎯 What this stage does

The **Drafting Phase** translates every `CORE` and `SUPPORT` asset from Triage into target-platform code — PySpark jobs, Snowpark scripts, SQL transformations, or whatever your cartridge specifies.

The goal at this stage is **to make it work**, not to make it perfect. The generated code is a faithful 1:1 translation of your legacy logic, preserving all transformations, business rules, and dependencies.

---

## ⚙️ What you can configure

### Cartridge Settings
The **Cartridge** defines the output target for the generated code. Configure:

| Option | Description |
|---|---|
| **Target Platform** | The destination tech stack (PySpark, Snowpark, Databricks, etc.). |
| **Output Format** | File naming conventions and folder structure of generated files. |
| **Dialect Rules** | Platform-specific SQL/Python syntax adjustments. |

### Cartridge Prompt
Fine-tune the AI prompt used to generate the code. You can adjust:
- Coding style preferences (e.g., logging verbosity, error handling patterns).
- Custom instructions for specific object types (e.g., how to handle cursors or temp tables).

### Target Schema
Review the proposed schema structure in the destination environment before running generation.

---

## ▶️ Actions

- **Run Pipeline** — Launches the Drafting Agent, which iterates through every triaged asset and generates the corresponding target code file.

> 💡 You can re-run the pipeline after adjusting the cartridge prompt without losing manually reviewed files.

---

## 📊 Reports & Views

| View | Description |
|---|---|
| **Pipeline Status** | Real-time progress indicator showing how many objects have been generated. |
| **Execution Logs** | Detailed logs per object — shows warnings for unsupported constructs. |
| **Generation Summary** | Aggregated stats: total files generated, success rate, warnings count. |
| **Output Files** | Browse all generated code files organized by object type. |
| **Generation Stats** | Quality metrics of the generated code (complexity, line counts, coverage). |

---

## ✅ Done when...

All `CORE` and `SUPPORT` assets show a **Generated** status with no blocking errors. Warnings are acceptable — they indicate constructs that may need manual review in the Refinement phase.
