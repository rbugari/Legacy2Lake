# Drafting Phase

> Stage 2 of 5. Drafting generates the first working target artifacts.

## Start here

Drafting now lands on an **Overview** page instead of jumping straight into logs or a random subsection.

Use the phase home to:

- check whether Drafting is only approved or already running
- launch the pipeline
- review output summaries
- open generated files
- adjust cartridge settings before re-running

## What this stage does

Drafting produces the first target implementation for the assets approved in Triage.

This stage is intentionally baseline-oriented:

- generate something faithful enough to review
- keep the target and cartridge rules consistent
- surface warnings and unsupported cases early
- prepare better input for Refinement and Governance

## What you can configure

| Area | What it controls |
|---|---|
| **Cartridge Settings** | Target platform, output conventions, and generation mode. |
| **Cartridge Prompt** | Platform-owned prompt layer used to steer generation behavior. |
| **Target Schema** | Structural reference for the generated target assets. |

## Main action

- **Run Pipeline**: starts the Drafting pipeline and moves the execution focus to progress and logs.

If the phase is already approved but not running yet, the Overview page should be your main starting point.

## Views you should use

| View | When to use it |
|---|---|
| **Overview** | Best landing page for the phase. |
| **Pipeline Status** | Use when the pipeline is running. |
| **Execution Logs** | Use for troubleshooting and progress details. |
| **Generation Summary** | Review generated asset counts and completion state. |
| **Output Files** | Inspect generated code artifacts. |
| **Generation Stats** | Review aggregate quality or volume signals. |

## Done when

Drafting is in good shape when:

- the pipeline completed without blocking failures
- the main output files are present
- the generated baseline looks reasonable for the chosen target
- the team is ready to move into Refinement
