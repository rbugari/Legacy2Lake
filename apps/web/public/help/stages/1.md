# 🔬 Triage Phase

> **Stage 1 of 5** · AI-assisted classification of every discovered object.

---

## 🎯 What this stage does

The **Triage Phase** uses an AI agent to analyze every object discovered in Stage 0 and assign it a **migration role**, a **load strategy**, and a **risk level**. The result is a structured migration blueprint ready for code generation.

You can review, override, and fine-tune every AI decision before moving forward.

---

## ⚙️ What you can configure

### Object Classification
Each asset is assigned one of three roles:

| Role | Meaning |
|---|---|
| `CORE` | Critical objects that will be fully migrated and translated to the target platform. |
| `SUPPORT` | Auxiliary objects migrated as-is or with minimal transformation. |
| `IGNORED` | Objects excluded from migration (e.g., deprecated tables, dev-only artifacts). |

### Load Strategy
Define how each table will be populated in the target environment:

- `Full Load` — Full refresh on every pipeline run.
- `Incremental` — Only new or changed records are loaded.
- `SCD Type 2` — Tracks historical changes with version rows.
- `Truncate & Load` — Clears and fully reloads on each run.

### PII Detection
The AI flags columns likely to contain sensitive personal data. Review and confirm these labels before proceeding.

---

## ▶️ Actions

- **Run Analysis** — Executes the Triage Agent, which evaluates all assets, infers relationships, assigns classifications, and generates the initial load strategy recommendations.
- **Save Triage State** — Manually saves your overrides and customizations from the Grid view.

> 💡 You can re-run the Triage Agent at any time. Your manual overrides are preserved unless you explicitly reset them.

---

## 📊 Views & Reports

| View | Description |
|---|---|
| **Graph** | Interactive node graph showing asset relationships and data flow direction. |
| **Grid** | Spreadsheet-like table to bulk-edit classifications, strategies, and PII tags. |
| **Schema** | Side-by-side view of legacy schema vs. proposed target schema. |
| **Mapping** | Field-level column mapping between source and destination objects. |
| **Origin** | Breakdown by source system — useful for multi-system migrations. |
| **Transformations** | Lists all detected transformation rules applied during triage. |
| **Source Queries** | Shows the underlying SQL logic for views and procedures. |
| **Code Quality** | Internal quality score per object based on complexity and maintainability. |
| **PII Detection** | Summary of all flagged sensitive fields grouped by table. |
| **Table Registry** | Complete inventory with classification and strategy per table. |

---

## ✅ Done when...

All assets have a **role** (`CORE`, `SUPPORT`, or `IGNORED`) and a **load strategy** assigned. PII flags should be reviewed and confirmed. Once satisfied, proceed to **Drafting** to generate the target code.
