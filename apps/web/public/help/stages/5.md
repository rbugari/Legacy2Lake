# 🚀 Handover Phase

> **Stage 5 of 5** · Package, export, and deliver the complete migration output.

---

## 🎯 What this stage does

The **Handover Phase** is the final stage of the Legacy2Lake pipeline. It bundles all migration artifacts — generated code, documentation, lineage maps, and the certification report — into a structured **Handover Package** ready for delivery to the target team or deployment environment.

This is the stage where the migration officially transfers from the migration platform to the engineering or data team responsible for go-live.

---

## ⚙️ What you can configure

### Export Options
Choose what to include in the handover package and in what format:

| Option | Description |
|---|---|
| **Code Files** | Include all refined target-platform scripts (PySpark, Snowpark, etc.). |
| **Documentation** | Include Technical Docs, Data Dictionary, Lineage Map, and Runbook. |
| **Certification Report** | Attach the formal audit/certification summary. |
| **Manifest File** | A machine-readable JSON manifest of all packaged artifacts and their metadata. |
| **Export Format** | ZIP archive, Git commit, or cloud storage upload (S3, Azure Blob, GCS). |

---

## ▶️ Actions

- **Export Options** — Opens the export configuration panel. Select your desired output format and content scope, then confirm to generate and download the package.

> 💡 The Handover Package is immutable once generated. If you need to make changes, return to the relevant stage, apply the fix, and regenerate the package.

---

## 📊 Reports & Views

| View | Description |
|---|---|
| **Handover Package** | Status panel showing the contents of the current or last generated package. Includes file counts, sizes, and timestamps. |

---

## 🎉 Done when...

The **Handover Package** is generated and delivered. The migration is complete!

After handover, the receiving team should:
1. Deploy the generated code to the target environment.
2. Run the Runbook to validate the first full pipeline execution.
3. Verify data quality against the source using the Data Dictionary.
4. Archive the package for audit trail purposes.
