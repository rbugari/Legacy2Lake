# Refinement Phase

> Stage 3 of 5. Refinement improves, validates, and prepares generated output for governance.

## Start here

This phase now has an **Overview** landing page. Use it to:

- see whether Refinement has not started, is running, or already finished
- launch the refinement run
- jump to summary, comparison, and settings
- keep your place if you leave the phase and return later

## What this stage does

Refinement works on Drafting output to improve target quality and reduce obvious technical debt before Governance.

Typical focus areas:

- schema alignment
- target-platform conventions
- structural cleanup
- comparison against the draft output
- quality improvement signals

## What you can configure

| Area | Why it matters |
|---|---|
| **Design Settings** | Controls the overall refinement direction and constraints. |
| **Cartridge Prompts** | Lets the platform-owned prompt layer steer how refinement should behave. |

## Main action

- **Run Refinement**: executes the refinement workflow over the current generated output.

## Views you should use

| View | When to use it |
|---|---|
| **Overview** | Best landing page for the phase. |
| **Status Dashboard** | Best when the phase is currently running. |
| **Refinement Summary** | Review the before/after state and main outputs. |
| **File Explorer / Comparison** | Inspect files and compare refined output with the draft baseline. |
| **Execution Logs** | Use when refinement is slow, confusing, or failed. |
| **Schema Validation** | Use before approving Governance. |

## Done when

Refinement is ready when:

- the important files were processed
- the summary looks consistent
- the refined output is better than the draft baseline
- there are no unresolved critical validation issues
