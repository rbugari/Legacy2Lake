# 🛠️ Refinement Phase

> **Stage 3 of 5** · Optimization, quality review, and schema validation.

---

## 🎯 What this stage does

The **Refinement Phase** takes the raw generated code from Drafting and systematically improves it. The AI agent reviews each file for:

- **Performance anti-patterns** — unnecessary loops, missing partitioning, inefficient joins.
- **Target platform best practices** — rewriting constructs to be idiomatic for the destination stack.
- **Schema alignment** — confirming that generated DDL matches the expected target schema.

After refinement, each file is significantly closer to production-ready.

---

## ⚙️ What you can configure

### Design Settings
Define the optimization rules the Refinement Agent should apply:

| Setting | Description |
|---|---|
| **Optimization Level** | How aggressively to refactor (conservative, standard, aggressive). |
| **Target Patterns** | Specific design patterns to enforce (e.g., partitioning by date, medallion architecture). |
| **Preserve Comments** | Whether to keep original inline comments from the legacy code. |

### Cartridge Prompts
Similar to Drafting, you can customize the AI instructions used during refinement to steer style decisions and naming conventions.

---

## ▶️ Actions

- **Run Refinement** — Executes the Refinement Agent over all previously generated files. Only files that pass quality checks are updated.

> ⚠️ Running Refinement will overwrite the Drafting output. Make sure to review the Generation Summary before proceeding.

---

## 📊 Reports & Views

| View | Description |
|---|---|
| **Status Dashboard** | Overview of refinement progress — how many files have been processed and their status. |
| **Refinement Summary** | Before/after comparison of quality scores per object. |
| **File Explorer** | Browse the refined output files with diff highlighting vs. the original draft. |
| **Execution Logs** | Step-by-step log of the refinement agent's decisions per file. |
| **Quality Score** | Aggregate quality improvement metric comparing pre- vs. post-refinement. |
| **Schema Validation** | Confirms that the generated DDL aligns with the target schema definition. |

---

## ✅ Done when...

The **Quality Score** shows an improvement over the Drafting baseline, **Schema Validation** passes with no critical errors, and the **Status Dashboard** shows all files as `REFINED`. Proceed to **Governance** for documentation generation.
