# 🔍 Discovery Phase

> **Stage 0 of 5** · The foundation of your entire migration journey starts here.

---

## 🎯 What this stage does

The **Discovery Phase** performs a deep forensic scan of your legacy codebase. It catalogs every object — tables, views, stored procedures, functions, triggers, and their inter-dependencies — **without touching or moving any business data**.

The result is a complete inventory used to drive all subsequent stages automatically.

---

## ⚙️ What you can configure

| Section | What it does |
|---|---|
| **Tribal Knowledge** | Upload ZIP, SQL, or XML files with extra project context (ERDs, specs, runbooks). |
| **File Pre-Classification** | Preview how the scanner has categorized your source files before running the scan. |

---

## ▶️ Actions

- **Run Forensic Scan** — Launches **Agent S**, which parses all uploaded files, extracts object metadata, builds the dependency graph, and delivers the final inventory count.

> 💡 You can upload multiple files and re-run the scan at any time without losing previous results.

---

## 📊 Reports available after running

| Report | Description |
|---|---|
| **Forensic Assessment** | Full vulnerability and complexity report per object. |
| **Tech Validation** | Summary of supported and unsupported constructs found. |
| **File Pre-Classification** | Object-by-object breakdown of what was detected and how it was classified. |
| **Execution Logs** | Real-time logs from the scan process — useful for troubleshooting parsing errors. |

---

## ✅ Done when...

The stage is complete when the **Forensic Assessment** report shows 0 unresolved errors and your total asset count looks correct. You can then proceed to **Triage**.
