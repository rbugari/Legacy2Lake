# Discovery Phase

> Stage 0 of 5. Discovery is the intake and validation phase for the project.

## Start here

When you enter this phase, the workspace lands on an **Overview** page. Use it as the phase home:

- review the current discovery status
- confirm file counts and assessment score
- decide whether you need to add context before running
- jump to scan, assessment, files, or logs

## What this stage does

Discovery scans the uploaded repository and support files to build the initial inventory used by the rest of the platform.

Typical inputs include:

- SQL and DDL
- SSIS `.dtsx`
- manifests and project files
- support files such as parameters, connection managers, and tribal knowledge

The result is a first technical understanding of what exists, what is likely migrable, and what still needs clarification.

## What you can configure

| Section | What it does |
|---|---|
| **Tribal Knowledge** | Add optional project-specific context, notes, specs, or supporting files. |
| **File Pre-Classification** | Review how files were recognized before or after the scan. |

## Main action

- **Run Forensic Scan**: launches the discovery workflow and produces the first viability and inventory view.

You can re-run Discovery after adding new files or context.

## Views you should use

| View | When to use it |
|---|---|
| **Overview** | Best landing page for the phase. Start here. |
| **Forensic Assessment** | Review viability, blockers, and score. |
| **Tech Validation** | Check detected technologies and suspicious unsupported patterns. |
| **File Pre-Classification** | Inspect what the platform recognized in the uploaded source. |
| **Execution Logs** | Use when a scan looks slow, incomplete, or suspicious. |

## Done when

Discovery is in good shape when:

- the inventory count looks reasonable
- the detected technology makes sense
- there are no unexplained blockers
- the team has enough context to move into Triage
