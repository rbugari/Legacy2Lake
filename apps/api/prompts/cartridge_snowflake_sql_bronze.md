### 2. SNOWFLAKE SQL PLATFORM NOTES

**⚠️ CRITICAL DIFFERENCE FROM SNOWPARK CARTRIDGE:**
- This cartridge generates **SQL Stored Procedures**, NOT Python code.
- Output is a `CREATE OR REPLACE PROCEDURE` block with SQL body.
- Called by orchestrator via `CALL schema.sp_bronze_{{asset_name}}(param1, ...)`.
- No Python, no DataFrame API, no `session` object. Pure Snowflake SQL.
- All parameters come in as **SP arguments** (typed SQL values), not a Python dict.

**Snowflake SQL Bronze advantages over Snowpark:**
- Zero external runtime — runs 100% inside Snowflake engine.
- `COPY INTO` is the most performant bulk ingestion primitive in Snowflake.
- Procedural SQL (Snowflake Scripting) supports `IF`, `FOR`, `WHILE`, `LET`, `RETURN`.
- Easier for DBA-oriented teams; no Python environment needed.
- `EXECUTE IMMEDIATE` enables dynamic SQL when table/column names vary.

### 3. ZERO-HARDCODE POLICY
**❌ FORBIDDEN: Hardcoded values inside procedure body**
- No literal database/schema names (use parameters or session context)
- No hardcoded stage names, file paths, role names, warehouse names
- No static column lists repeated without derivation

**✅ REQUIRED: All from stored procedure parameters**
```sql
CREATE OR REPLACE PROCEDURE {{schema}}.SP_BRONZE_{{ASSET_NAME}}(
    P_DATABASE      STRING,      -- Target Snowflake database
    P_BRONZE_SCHEMA STRING,      -- Target bronze schema (e.g. 'BRONZE_RAW')
    P_TABLE_NAME    STRING,      -- Target table name (UPPERCASE)
    P_STAGE_PATH    STRING,      -- @stage/path/to/files or empty string
    P_FILE_FORMAT   STRING,      -- 'CSV' | 'PARQUET' | 'JSON'
    P_LOAD_MODE     STRING,      -- 'MERGE' | 'OVERWRITE' | 'APPEND'
    P_BATCH_DATE    DATE         -- Watermark / batch control date
)
```

### 4. PROCEDURE STRUCTURE (Snowflake Scripting)

```sql
CREATE OR REPLACE PROCEDURE {{schema}}.SP_BRONZE_{{ASSET_NAME}}(
    P_DATABASE      STRING,
    P_BRONZE_SCHEMA STRING,
    P_TABLE_NAME    STRING,
    P_STAGE_PATH    STRING,
    P_FILE_FORMAT   STRING,
    P_LOAD_MODE     STRING,
    P_BATCH_DATE    DATE
)
RETURNS VARIANT         -- Returns JSON-like result object {status, rows_loaded}
LANGUAGE SQL
EXECUTE AS CALLER       -- Runs with the caller's privileges (no OWNER bypass)
AS
$$
DECLARE
    v_target_table  STRING  DEFAULT P_DATABASE || '.' || P_BRONZE_SCHEMA || '.' || P_TABLE_NAME;
    v_rows_loaded   INTEGER DEFAULT 0;
    v_rows_before   INTEGER DEFAULT 0;
    v_error_msg     STRING;
BEGIN

    -- ============================================================
    -- [EXTRACT] Stage loading via COPY INTO
    -- ============================================================

    -- [TRANSFORM] Audit column injection via staging CTE (see Section 5)

    -- [LOAD] MERGE / OVERWRITE / APPEND (see Section 6)

    -- [RETURN]
    RETURN OBJECT_CONSTRUCT(
        'status',       'SUCCESS',
        'target_table', v_target_table,
        'rows_loaded',  v_rows_loaded,
        'batch_date',   P_BATCH_DATE::STRING
    );

EXCEPTION
    WHEN OTHER THEN
        v_error_msg := SQLERRM;
        RETURN OBJECT_CONSTRUCT(
            'status',  'ERROR',
            'message', v_error_msg
        );
END;
$$;
```

### 5. COPY INTO PATTERNS (Primary Bronze Ingestion)

**Pattern A: COPY INTO from External/Internal Stage (CSV)**
```sql
-- Create a landing/staging table first (DDL-only, no audit cols)
LET v_staging_table STRING DEFAULT v_target_table || '_STAGING';

EXECUTE IMMEDIATE '
    CREATE TABLE IF NOT EXISTS ' || v_staging_table || '
    LIKE ' || v_target_table || '
    COPY GRANTS
';

-- COPY INTO staging (raw ingest — no transformations here)
EXECUTE IMMEDIATE '
    COPY INTO ' || v_staging_table || '
    FROM ' || P_STAGE_PATH || '
    FILE_FORMAT = (
        TYPE = CSV
        SKIP_HEADER = 1
        FIELD_OPTIONALLY_ENCLOSED_BY = ''"''
        NULL_IF = ('''', ''NULL'', ''N/A'')
        EMPTY_FIELD_AS_NULL = TRUE
        DATE_FORMAT = ''AUTO''
        TIMESTAMP_FORMAT = ''AUTO''
    )
    ON_ERROR = CONTINUE
    PURGE = FALSE
';
```

**Pattern B: COPY INTO from Stage (PARQUET)**
```sql
EXECUTE IMMEDIATE '
    COPY INTO ' || v_staging_table || '
    FROM (
        SELECT
            $1:COLUMN_A::STRING    AS COLUMN_A,
            $1:COLUMN_B::INTEGER   AS COLUMN_B,
            $1:AMOUNT::NUMBER(18,4) AS AMOUNT,
            $1:LOAD_DATE::DATE     AS LOAD_DATE
        FROM ' || P_STAGE_PATH || '
    )
    FILE_FORMAT = (TYPE = PARQUET)
    ON_ERROR = CONTINUE
';
```

**Pattern C: INSERT INTO ... SELECT (source already in Snowflake)**
```sql
LET v_source_table STRING DEFAULT P_DATABASE || '.' || P_BRONZE_SCHEMA || '.' || :source_table_param;

EXECUTE IMMEDIATE '
    INSERT INTO ' || v_staging_table || '
    SELECT *
    FROM ' || v_source_table || '
    WHERE LOAD_DATE >= ''' || P_BATCH_DATE::STRING || '''
';
```

### 6. AUDIT COLUMN INJECTION (Bronze Layer)

After staging load, transfer to Bronze target with audit columns:

```sql
-- Step 2: Move from staging to Bronze with audit columns
EXECUTE IMMEDIATE '
    INSERT INTO ' || v_target_table || '
    SELECT
        s.*,
        CURRENT_TIMESTAMP()                     AS _INGESTION_TIMESTAMP,
        CURRENT_DATE()                          AS _INGESTION_DATE,
        ''' || P_STAGE_PATH || '''             AS _SOURCE_FILE,
        SHA2(
            CONCAT_WS(''||'',
                s.BUSINESS_KEY_1::STRING,
                s.BUSINESS_KEY_2::STRING
            ), 256
        )                                       AS _RECORD_HASH
    FROM ' || v_staging_table || ' s
';

-- Clean up staging
EXECUTE IMMEDIATE 'TRUNCATE TABLE ' || v_staging_table;
```

### 7. LOAD MODES (MERGE / OVERWRITE / APPEND)

**MERGE (idempotent — recommended default):**
```sql
EXECUTE IMMEDIATE '
    MERGE INTO ' || v_target_table || ' t
    USING (
        SELECT
            s.*,
            CURRENT_TIMESTAMP()  AS _INGESTION_TIMESTAMP,
            CURRENT_DATE()       AS _INGESTION_DATE,
            ''' || P_STAGE_PATH || ''' AS _SOURCE_FILE,
            SHA2(CONCAT_WS(''||'', s.BK_COL1::STRING, s.BK_COL2::STRING), 256) AS _RECORD_HASH
        FROM ' || v_staging_table || ' s
    ) src
    ON t.BUSINESS_KEY = src.BUSINESS_KEY
    WHEN MATCHED THEN UPDATE SET
        t.COL_A               = src.COL_A,
        t._INGESTION_TIMESTAMP = src._INGESTION_TIMESTAMP,
        t._RECORD_HASH         = src._RECORD_HASH
    WHEN NOT MATCHED THEN INSERT
        (BUSINESS_KEY, COL_A, _INGESTION_TIMESTAMP, _INGESTION_DATE, _SOURCE_FILE, _RECORD_HASH)
    VALUES
        (src.BUSINESS_KEY, src.COL_A, src._INGESTION_TIMESTAMP,
         src._INGESTION_DATE, src._SOURCE_FILE, src._RECORD_HASH)
';
```

**OVERWRITE (full refresh):**
```sql
IF (P_LOAD_MODE = 'OVERWRITE') THEN
    EXECUTE IMMEDIATE 'TRUNCATE TABLE ' || v_target_table;
END IF;
EXECUTE IMMEDIATE 'INSERT INTO ' || v_target_table || ' SELECT * FROM ' || v_staging_table;
```

**APPEND (incremental batch):**
```sql
EXECUTE IMMEDIATE '
    INSERT INTO ' || v_target_table || '
    SELECT * FROM ' || v_staging_table || '
    WHERE _INGESTION_DATE > (
        SELECT COALESCE(MAX(_INGESTION_DATE), ''1900-01-01'')
        FROM ' || v_target_table || '
    )
';
```

### 9. ROW COUNT CAPTURE & LOGGING

Snowflake SQL has no `logger` — use `RESULT_SCAN` and `SYSTEM$LOG` or return metrics:

```sql
-- Capture rows loaded via COPY INTO result
LET copy_result RESULTSET DEFAULT (
    COPY INTO ...
);
-- v_rows_loaded comes from RESULT_SCAN of last COPY INTO
SELECT COUNT(*) INTO v_rows_loaded FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));

-- For INSERT/MERGE, use SQLROWCOUNT
INSERT INTO ...;
v_rows_loaded := SQLROWCOUNT;

-- Optional: log to audit table (orchestrator-managed)
INSERT INTO {{schema}}.L2L_EXECUTION_LOG
    (ASSET_NAME, LAYER, BATCH_DATE, ROWS_LOADED, STATUS, EXECUTED_AT)
VALUES
    ('{{asset_name}}', 'BRONZE', :P_BATCH_DATE, :v_rows_loaded, 'SUCCESS', CURRENT_TIMESTAMP());
```

### 11. SNOWFLAKE SQL NAMING CONVENTIONS
- All identifiers: `UPPER_SNAKE_CASE`
- Procedure names: `SP_{LAYER}_{ASSET_NAME}` (e.g. `SP_BRONZE_ORDERS`)
- No double-quoted identifiers unless intentionally case-sensitive
- Temporary/staging tables: `{TARGET_TABLE}_STAGING`
- All string literals in SQL within `EXECUTE IMMEDIATE`: escape single-quotes by doubling (`''`)

### 12. SNOWFLAKE NATIVE OPTIMIZATION HINTS

**QUERY_TAG — Cost Attribution (MANDATORY for L2L workloads):**
```sql
-- Add at the very START of procedure body, before any DML:
ALTER SESSION SET QUERY_TAG = 'L2L|BRONZE|{{asset_name}}';
-- Queryable: SELECT * FROM TABLE(INFORMATION_SCHEMA.QUERY_HISTORY()) WHERE QUERY_TAG LIKE 'L2L|BRONZE|%';
```

**TRANSIENT vs. PERMANENT Tables — Storage Cost:**
```sql
-- Bronze STAGING tables: ALWAYS TRANSIENT (no Fail-Safe = ~50% lower storage cost)
CREATE OR REPLACE TRANSIENT TABLE {{database}}.{{schema}}.{{table}}_STAGING (...)
...
-- Bronze TARGET tables: TRANSIENT acceptable (raw data is re-ingestible from GCS/S3/ADLS)
-- Only use PERMANENT if SLA requires 7-day Fail-Safe recovery capability.
```

**COPY INTO Performance Options:**
```sql
COPY INTO {{database}}.{{schema}}.{{table}}_STAGING
FROM @{{stage_name}}/{{path}}/
FILE_FORMAT   = (TYPE = PARQUET)           -- or CSV, JSON, AVRO
PATTERN       = '.*\.parquet'              -- filter by extension
PURGE         = TRUE                       -- auto-delete stage files after load
ON_ERROR      = 'SKIP_FILE'               -- skip bad files, continue
FORCE         = FALSE                      -- skip already-loaded files (idempotent)
SIZE_LIMIT    = 1073741824;                -- cap per-run to 1GB to control warehouse time
-- Parallel ingestion: BQ auto-splits large files. Provide wildcard for parallelism:
--   FROM @stage/orders/  (all files under /orders/ load in parallel)
```

**Validate Stage Before COPY (orchestrator pre-check):**
```sql
-- Return file list + sizes — run from orchestrator before triggering COPY:
LIST @{{stage_name}}/{{path}}/;
-- If list is empty → skip COPY (avoids 0-row runs consuming warehouse credits)
```

**Warehouse Sizing Hints (add as comment in procedure header):**
