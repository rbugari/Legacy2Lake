### 2. SNOWFLAKE SQL PLATFORM NOTES

**⚠️ CRITICAL: This cartridge generates SQL Stored Procedures, NOT Python/Snowpark code.**
- Output is a `CREATE OR REPLACE PROCEDURE` with SQL body (Snowflake Scripting).
- No `session` object, no DataFrame API, no Python imports.
- Procedural logic uses `DECLARE`, `BEGIN...END`, `IF`, `FOR`, `LET`, `EXECUTE IMMEDIATE`.
- `QUALIFY ROW_NUMBER() OVER (...) = 1` is the native Snowflake deduplication idiom.
- `MERGE INTO` is purely declarative SQL — no Snowpark `.merge()` API.

**Snowflake SQL Silver advantages:**
- `QUALIFY` clause is a Snowflake extension — extremely clean deduplication without subqueries.
- `MERGE INTO` with complex WHEN clauses covers SCD Type 2 natively in SQL.
- CTE-based quality checks are transparent, readable, and auditable.
- No cluster management needed — Snowflake micro-partitions are self-optimizing.

### 4. PROCEDURE STRUCTURE

```sql

    P_DATABASE        STRING,
    P_BRONZE_SCHEMA   STRING,

    v_rows_merged   INTEGER DEFAULT 0;
    v_error_msg     STRING;
BEGIN

    -- [EXTRACT + DEDUP] Section 5
    -- [QUALITY]         Section 6
    -- [SCD TYPE 2 MERGE] Section 7
    -- [RETURN]

    RETURN OBJECT_CONSTRUCT(
        'status',         'SUCCESS',
        'silver_table',   v_silver_full,
```

### 5. DEDUPLICATION (Snowflake QUALIFY Idiom)

**`QUALIFY` is a Snowflake-specific clause — the cleanest deduplication in SQL:**

```sql
-- Create a deduplicated CTE from Bronze — QUALIFY is Snowflake-native
EXECUTE IMMEDIATE '
    CREATE OR REPLACE TRANSIENT TABLE ' || P_DATABASE || '.' || P_SILVER_SCHEMA || '.DEDUP_' || P_TARGET_TABLE || ' AS
    SELECT *
    FROM ' || v_bronze_full || '
    WHERE _INGESTION_DATE >= ''' || P_BATCH_DATE::STRING || '''
    QUALIFY ROW_NUMBER() OVER (
        PARTITION BY BUSINESS_KEY_1, BUSINESS_KEY_2     -- replace with P_BUSINESS_KEYS
        ORDER BY _INGESTION_TIMESTAMP DESC
    ) = 1
';
```

**Dynamic deduplication using P_BUSINESS_KEYS parameter:**
```sql
-- Parse P_BUSINESS_KEYS ('BK1,BK2') into PARTITION BY clause
LET v_partition_by STRING DEFAULT
    'PARTITION BY ' || REPLACE(P_BUSINESS_KEYS, ',', ', ');

LET v_dedup_sql STRING DEFAULT '
    CREATE OR REPLACE TRANSIENT TABLE ' || v_dedup_table || ' AS
    SELECT * EXCLUDE (_INGESTION_TIMESTAMP, _INGESTION_DATE, _SOURCE_FILE, _RECORD_HASH)
    FROM (
        SELECT *,
            ROW_NUMBER() OVER (' || v_partition_by || ' ORDER BY _INGESTION_TIMESTAMP DESC) AS _RN
        FROM ' || v_bronze_full || '
        WHERE _INGESTION_DATE >= ''' || P_BATCH_DATE::STRING || '''
    )
    WHERE _RN = 1
';
EXECUTE IMMEDIATE v_dedup_sql;
```

### 6. DATA QUALITY (CTE-Based, Non-Blocking)

```sql
-- Quality check via TRANSIENT TABLE — flag NULLs, don't drop records
EXECUTE IMMEDIATE '
    CREATE OR REPLACE TRANSIENT TABLE ' || v_quality_table || ' AS
    SELECT
        *,
        CASE
            WHEN BUSINESS_KEY_1 IS NULL OR BUSINESS_KEY_2 IS NULL
            THEN FALSE ELSE TRUE
        END AS IS_COMPLETE_RECORD,
        CASE
            WHEN AMOUNT < 0 THEN FALSE ELSE TRUE
        END AS IS_AMOUNT_VALID
    FROM ' || v_dedup_table || '
';

-- Log quality stats (non-blocking — Silver proceeds regardless)
LET v_incomplete INTEGER;
EXECUTE IMMEDIATE '
    SELECT COUNT(*) FROM ' || v_quality_table || ' WHERE IS_COMPLETE_RECORD = FALSE'
INTO v_incomplete;

IF (v_incomplete > 0) THEN
    -- Optionally insert to error log table (orchestrator-defined)
    EXECUTE IMMEDIATE '
        INSERT INTO ' || P_DATABASE || '.AUDIT.L2L_QUALITY_LOG
        SELECT CURRENT_TIMESTAMP(), ''' || P_TARGET_TABLE || ''',
               ''SILVER'', ''NULL_BUSINESS_KEY'', ' || v_incomplete || '
    ';
END IF;
```

### 7. SCD TYPE 2 — SNOWFLAKE MERGE INTO

**Step 1 — Create Silver table if not exists:**
```sql
EXECUTE IMMEDIATE '
    CREATE TABLE IF NOT EXISTS ' || v_silver_full || ' (
        -- Business columns (mirror of source, minus Bronze audit cols)
        BUSINESS_KEY_1  STRING        NOT NULL,
        BUSINESS_KEY_2  STRING,
        ATTRIBUTE_A     STRING,
        AMOUNT          NUMBER(18,4),
        -- SCD Type 2 Silver columns
        VALID_FROM      TIMESTAMP_NTZ NOT NULL,
        VALID_UNTIL     TIMESTAMP_NTZ,
        IS_CURRENT      BOOLEAN       NOT NULL DEFAULT TRUE,
        RECORD_VERSION  INTEGER       NOT NULL DEFAULT 1,
        -- Silver audit
        SILVER_CREATED_AT TIMESTAMP_NTZ,
        SILVER_UPDATED_AT TIMESTAMP_NTZ
    )
    COMMENT = ''L2L Silver SCD2: {{asset_name}}''
';
```

**Step 2 — SCD Type 2 MERGE (two-step pattern):**
```sql
-- STEP A: Expire changed active records
EXECUTE IMMEDIATE '
    MERGE INTO ' || v_silver_full || ' t
    USING ' || v_quality_table || ' s
    ON t.BUSINESS_KEY_1 = s.BUSINESS_KEY_1
       AND t.BUSINESS_KEY_2 = s.BUSINESS_KEY_2
       AND t.IS_CURRENT = TRUE
    WHEN MATCHED AND (
        t.ATTRIBUTE_A <> s.ATTRIBUTE_A OR
        t.AMOUNT      <> s.AMOUNT
        -- add all trackable attribute comparisons
    ) THEN UPDATE SET
        t.VALID_UNTIL        = CURRENT_TIMESTAMP(),
        t.IS_CURRENT         = FALSE,
        t.SILVER_UPDATED_AT  = CURRENT_TIMESTAMP()
';

-- STEP B: Insert new versions (new + changed records)
EXECUTE IMMEDIATE '
    INSERT INTO ' || v_silver_full || '
        (BUSINESS_KEY_1, BUSINESS_KEY_2, ATTRIBUTE_A, AMOUNT,
         VALID_FROM, VALID_UNTIL, IS_CURRENT, RECORD_VERSION,
         SILVER_CREATED_AT, SILVER_UPDATED_AT)
    SELECT
        s.BUSINESS_KEY_1,
        s.BUSINESS_KEY_2,
        s.ATTRIBUTE_A,
        s.AMOUNT,
        CURRENT_TIMESTAMP()     AS VALID_FROM,
        NULL                    AS VALID_UNTIL,
        TRUE                    AS IS_CURRENT,
        COALESCE(
            (SELECT MAX(t2.RECORD_VERSION) + 1
             FROM ' || v_silver_full || ' t2
             WHERE t2.BUSINESS_KEY_1 = s.BUSINESS_KEY_1
               AND t2.BUSINESS_KEY_2 = s.BUSINESS_KEY_2), 1
        )                       AS RECORD_VERSION,
        CURRENT_TIMESTAMP()     AS SILVER_CREATED_AT,
        CURRENT_TIMESTAMP()     AS SILVER_UPDATED_AT
    FROM ' || v_quality_table || ' s
';

v_rows_merged := SQLROWCOUNT;
```

### 8. SIMPLE UPSERT (When `P_SCD_ENABLED = FALSE`)

```sql
IF (NOT P_SCD_ENABLED) THEN
    EXECUTE IMMEDIATE '
        MERGE INTO ' || v_silver_full || ' t
        USING ' || v_quality_table || ' s
        ON t.BUSINESS_KEY_1 = s.BUSINESS_KEY_1
           AND t.BUSINESS_KEY_2 = s.BUSINESS_KEY_2
        WHEN MATCHED THEN UPDATE SET
            t.ATTRIBUTE_A        = s.ATTRIBUTE_A,
            t.AMOUNT             = s.AMOUNT,
            t.SILVER_UPDATED_AT  = CURRENT_TIMESTAMP()
        WHEN NOT MATCHED THEN INSERT
            (BUSINESS_KEY_1, BUSINESS_KEY_2, ATTRIBUTE_A, AMOUNT,
             SILVER_CREATED_AT, SILVER_UPDATED_AT)
        VALUES
            (s.BUSINESS_KEY_1, s.BUSINESS_KEY_2, s.ATTRIBUTE_A, s.AMOUNT,
             CURRENT_TIMESTAMP(), CURRENT_TIMESTAMP())
    ';
END IF;
```

### 10. SNOWFLAKE NATIVE OPTIMIZATION HINTS

**QUERY_TAG — Cost Attribution (MANDATORY):**
```sql
ALTER SESSION SET QUERY_TAG = 'L2L|SILVER|{{asset_name}}';
```

**SEARCH OPTIMIZATION SERVICE — Point-Lookup Acceleration:**
```sql
-- Run ONCE after Silver table creation (outside the stored procedure, by DBA/orchestrator).
-- Enables fast point-lookups on IS_CURRENT and BUSINESS_KEY columns.
-- Cost: ~10–30% extra storage. Justified for Silver tables > 5M rows.
ALTER TABLE {{database}}.{{silver_schema}}.{{target_table}}
    ADD SEARCH OPTIMIZATION ON EQUALITY(BUSINESS_KEY_1, BUSINESS_KEY_2, IS_CURRENT);

-- Verify Search Optimization status:
SHOW TABLES LIKE '{{target_table}}' IN SCHEMA {{database}}.{{silver_schema}};
-- Look for SEARCH_OPTIMIZATION column = ON and SEARCH_OPTIMIZATION_BYTES_USED > 0
```

**CLUSTER BY — Auto-Maintenance + Health Check:**
```sql
-- Snowflake AUTO-RECLUSTERS tables with CLUSTER BY — no manual CLUSTER TABLE needed.
-- If DML is heavy (> 50% of rows changed per run), monitor clustering depth:
SELECT SYSTEM$CLUSTERING_INFORMATION(
    '{{database}}.{{silver_schema}}.{{target_table}}',
    '(VALID_FROM::DATE, BUSINESS_KEY_1)'
);
-- "average_depth" > 2.0 → trigger manual recluster:
-- ALTER TABLE {{database}}.{{silver_schema}}.{{target_table}} RECLUSTER;
```

**Result-Cacheable Silver View (avoid volatile functions in SELECT):**
```sql
-- Snowflake Result Cache (24h TTL) is invalidated by ANY volatile function in SELECT.
-- VW_SILVER_CURRENT must NOT include CURRENT_TIMESTAMP() in its SELECT list:
CREATE OR REPLACE VIEW {{database}}.{{silver_schema}}.VW_{{target_table}}_CURRENT AS
SELECT
    BUSINESS_KEY_1,
    BUSINESS_KEY_2,
    ATTRIBUTE_A,
    AMOUNT,
    VALID_FROM,
    RECORD_VERSION
    -- ✅ NO CURRENT_TIMESTAMP() here — result is cacheable for 24h
FROM {{database}}.{{silver_schema}}.{{target_table}}
WHERE IS_CURRENT = TRUE;
```

**Warehouse Sizing Hints:**
```sql
-- ⚙️ WAREHOUSE SIZING (SCD Type 2 MERGE is heavier than simple INSERT):

-- 5M – 50M active rows  → Small to Medium
```
