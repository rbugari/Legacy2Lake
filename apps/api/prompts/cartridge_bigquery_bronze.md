# BigQuery SQL — Bronze Layer Cartridge Rules

## 🎯 CRITICAL COMPLIANCE REQUIREMENTS (Zero-Hardcode Policy)

### 1. MANDATORY L2L MODERNIZATION TRACE HEADER
```sql
-- ================================================================
-- L2L MODERNIZATION TRACE: Bronze Layer - {{asset_name}}
-- ================================================================
-- Source Asset: {{source_asset_name}}
-- Source Technology: {{source_tech}}
-- Target Platform: Google BigQuery (Standard SQL Scripting)
-- Medallion Layer: bronze
-- Component Type: Data Ingestion Pipeline
-- Business Entity: {{business_entity}}
-- Load Strategy: {{load_strategy}}
-- Generated At: {{timestamp}}
-- Generated By: L2L Agent-C (Cartridge: BigQuery v1.0 - Bronze)
-- ================================================================
```

### 2. BIGQUERY PLATFORM NOTES

**⚠️ CRITICAL DIFFERENCES from Spark-based cartridges:**
- **No `spark` / `session` object.** BigQuery SQL runs inside the BQ engine. Orchestrator calls via `bq query`, Cloud Composer, or BigQuery Jobs API.
- **Naming**: `PROJECT.DATASET.TABLE` — never `catalog.schema.table`.
- **No Delta Lake / Iceberg.** BigQuery uses native columnar storage (Capacitor). No `.format("delta")`.
- **Stored Procedures**: `CREATE OR REPLACE PROCEDURE dataset.sp_name(IN param TYPE, OUT param TYPE) BEGIN ... END`.
- **Temp tables**: `CREATE TEMP TABLE name AS SELECT ...` — scoped to the BigQuery session/job.
- **MERGE**: `MERGE dataset.target T USING (...) S ON ... WHEN MATCHED ... WHEN NOT MATCHED ...` — standard BigQuery SQL.
- **Hashing for SK**: `TO_HEX(MD5(CONCAT(...)))` or `FARM_FINGERPRINT(CONCAT(...))` — both are BigQuery-native.
- **Partitioning**: Declared at DDL level (`PARTITION BY DATE(col)`). No runtime `.partitionBy()`.
- **Clustering**: Declared at DDL level (`CLUSTER BY col1, col2`). Replaces Spark `repartition`.
- **Credentials**: Managed by GCP IAM / Service Account — injected by orchestrator. NEVER in code.
- **External tables**: `EXTERNAL_QUERY()` to query Cloud SQL / AlloyDB directly from BQ SQL.
- **Bulk load**: `LOAD DATA INTO dataset.table FROM FILES (...)` for GCS-based ingestion.

### 3. ZERO-HARDCODE POLICY
**❌ FORBIDDEN: Hardcoded values anywhere**
- NO literal project IDs, dataset names, table names, GCS bucket paths
- NO Service Account keys or credentials
- NO static business key column names in procedure body

**✅ REQUIRED: All from procedure IN parameters**
```sql
CREATE OR REPLACE PROCEDURE {{dataset}}.SP_BRONZE_{{ASSET_NAME}}(
    IN p_project          STRING,     -- GCP project ID
    IN p_bronze_dataset   STRING,     -- Target BigQuery dataset (e.g. 'bronze_raw')
    IN p_table_name       STRING,     -- Target table name
    IN p_gcs_uri          STRING,     -- gs://bucket/path/*.parquet (or empty)
    IN p_file_format      STRING,     -- 'PARQUET' | 'CSV' | 'JSON' | 'AVRO'
    IN p_load_mode        STRING,     -- 'MERGE' | 'OVERWRITE' | 'APPEND'
    IN p_batch_date       DATE        -- Watermark / batch control date
)
```

### 4. PROCEDURE STRUCTURE (BigQuery Scripting)

```sql
CREATE OR REPLACE PROCEDURE {{dataset}}.SP_BRONZE_{{ASSET_NAME}}(
    IN  p_project         STRING,
    IN  p_bronze_dataset  STRING,
    IN  p_table_name      STRING,
    IN  p_gcs_uri         STRING,
    IN  p_file_format     STRING,
    IN  p_load_mode       STRING,
    IN  p_batch_date      DATE
)
BEGIN
    DECLARE v_target_table STRING DEFAULT CONCAT(p_project, '.', p_bronze_dataset, '.', p_table_name);
    DECLARE v_rows_loaded   INT64  DEFAULT 0;
    DECLARE v_rows_before   INT64  DEFAULT 0;

    -- [EXTRACT]   Section 5 — GCS or EXTERNAL_QUERY
    -- [TRANSFORM] Section 6 — audit columns via TEMP TABLE
    -- [LOAD]      Section 7 — MERGE / OVERWRITE / APPEND

    -- [RETURN] — BigQuery procedures use OUT params or log tables for metrics
    INSERT INTO {{dataset}}.L2L_EXECUTION_LOG
        (ASSET_NAME, LAYER, BATCH_DATE, ROWS_LOADED, STATUS, EXECUTED_AT)
    VALUES
        ('{{asset_name}}', 'BRONZE', p_batch_date, v_rows_loaded, 'SUCCESS', CURRENT_TIMESTAMP());

EXCEPTION WHEN ERROR THEN
    INSERT INTO {{dataset}}.L2L_EXECUTION_LOG
        (ASSET_NAME, LAYER, BATCH_DATE, ROWS_LOADED, STATUS, EXECUTED_AT, ERROR_MESSAGE)
    VALUES
        ('{{asset_name}}', 'BRONZE', p_batch_date, 0, 'ERROR', CURRENT_TIMESTAMP(), @@error.message);
    RAISE;
END;
```

### 5. EXTRACTION PATTERNS

**Pattern A: Load from GCS (LOAD DATA INTO — BigQuery native bulk ingestion)**
```sql
-- BigQuery native: load from GCS into a staging table
DECLARE v_staging STRING DEFAULT CONCAT(p_project, '.', p_bronze_dataset, '.', p_table_name, '_STAGING');

EXECUTE IMMEDIATE FORMAT("""
    LOAD DATA OVERWRITE `%s`
    FROM FILES (
        format = '%s',
        uris = ['%s'],
        skip_leading_rows = 1   -- only for CSV
    )
""", v_staging, p_file_format, p_gcs_uri);

SELECT @@row_count INTO v_rows_loaded;
```

**Pattern B: External Query (Cloud SQL / AlloyDB / Spanner as source)**
```sql
-- EXTERNAL_QUERY connects to Cloud SQL via BQ Omni / federated queries
-- Connection ID comes from p_project parameter (never hardcoded)
DECLARE v_conn_id STRING DEFAULT CONCAT(p_project, '.us.', 'cloud-sql-connection');

CREATE TEMP TABLE BRONZE_SOURCE AS
SELECT *
FROM EXTERNAL_QUERY(
    v_conn_id,
    FORMAT("SELECT * FROM schema.table WHERE load_date >= '%s'", CAST(p_batch_date AS STRING))
);
```

**Pattern C: Read from existing BigQuery source table**
```sql
CREATE TEMP TABLE BRONZE_SOURCE AS
SELECT *
FROM `project.source_dataset.source_table`    -- table ref from p_* params via EXECUTE IMMEDIATE
WHERE DATE(load_timestamp) >= p_batch_date;
```

### 6. AUDIT COLUMNS (Bronze Layer)
```sql
-- TEMP TABLE with L2L audit columns added
CREATE TEMP TABLE BRONZE_WITH_AUDIT AS
SELECT
    s.*,
    CURRENT_TIMESTAMP()                             AS _ingestion_timestamp,
    CURRENT_DATE()                                  AS _ingestion_date,
    p_gcs_uri                                       AS _source_file,
    TO_HEX(MD5(CONCAT(
        COALESCE(CAST(s.BUSINESS_KEY_1 AS STRING), ''), '||',
        COALESCE(CAST(s.BUSINESS_KEY_2 AS STRING), '')
    )))                                             AS _record_hash
FROM BRONZE_SOURCE s;
```

### 7. LOAD MODES

**MERGE (idempotent — recommended default):**
```sql
EXECUTE IMMEDIATE FORMAT("""
    MERGE `%s` T
    USING (SELECT * FROM BRONZE_WITH_AUDIT) S
    ON T.BUSINESS_KEY_1 = S.BUSINESS_KEY_1
       AND T.BUSINESS_KEY_2 = S.BUSINESS_KEY_2
    WHEN MATCHED THEN UPDATE SET
        T.COL_A               = S.COL_A,
        T._ingestion_timestamp = S._ingestion_timestamp,
        T._record_hash         = S._record_hash
    WHEN NOT MATCHED THEN INSERT ROW
""", v_target_table);

SET v_rows_loaded = @@row_count;
```

**OVERWRITE (full refresh — TRUNCATE + INSERT):**
```sql
IF p_load_mode = 'OVERWRITE' THEN
    EXECUTE IMMEDIATE FORMAT("TRUNCATE TABLE `%s`", v_target_table);
    EXECUTE IMMEDIATE FORMAT("INSERT INTO `%s` SELECT * FROM BRONZE_WITH_AUDIT", v_target_table);
    SET v_rows_loaded = @@row_count;
END IF;
```

**APPEND (incremental batch):**
```sql
IF p_load_mode = 'APPEND' THEN
    EXECUTE IMMEDIATE FORMAT("INSERT INTO `%s` SELECT * FROM BRONZE_WITH_AUDIT", v_target_table);
    SET v_rows_loaded = @@row_count;
END IF;
```

### 8. TABLE DDL (If-Not-Exists via INFORMATION_SCHEMA)
```sql
-- BigQuery has no CREATE TABLE IF NOT EXISTS directly in scripting for target tables
-- Check via INFORMATION_SCHEMA and create conditionally:

DECLARE v_table_exists BOOL DEFAULT FALSE;
SET v_table_exists = (
    SELECT COUNT(*) > 0
    FROM `region-us`.INFORMATION_SCHEMA.TABLES
    WHERE table_schema = p_bronze_dataset
      AND table_name   = p_table_name
      AND table_catalog = p_project
);

IF NOT v_table_exists THEN
    EXECUTE IMMEDIATE FORMAT("""
        CREATE TABLE `%s` (
            BUSINESS_KEY_1      STRING    NOT NULL,
            BUSINESS_KEY_2      STRING,
            COL_A               STRING,
            AMOUNT              NUMERIC,
            LOAD_DATE           DATE,
            -- L2L Bronze audit columns
            _ingestion_timestamp TIMESTAMP,
            _ingestion_date      DATE,
            _source_file         STRING,
            _record_hash         STRING
        )
        PARTITION BY _ingestion_date
        CLUSTER BY BUSINESS_KEY_1
        OPTIONS (description = 'L2L Bronze: {{asset_name}}')
    """, v_target_table);
END IF;
```

### 9. BIGQUERY NAMING & CONVENTIONS
- **Project.Dataset.Table** references: always backtick-quoted: `` `project.dataset.table` ``
- **UPPER_SNAKE_CASE** for column names within Bronze tables
- **Partition by DATE column**: always `PARTITION BY _ingestion_date` on Bronze tables
- **Cluster by business keys**: `CLUSTER BY BUSINESS_KEY_1` — BigQuery auto-maintains
- **`@@row_count`**: BigQuery system variable capturing last DML row count
- **`@@error.message`**: Available inside `EXCEPTION WHEN ERROR THEN` blocks

### 11. BIGQUERY NATIVE OPTIMIZATION HINTS

**Partition Expiration — Bronze Storage Lifecycle:**
```sql
-- Add to Bronze DDL for automatic storage lifecycle management:
CREATE TABLE `project.bronze_dataset.table` (...)
PARTITION BY _ingestion_date
CLUSTER BY BUSINESS_KEY_1
OPTIONS (
    description              = 'L2L Bronze: {{asset_name}}',
    partition_expiration_days = 365,   -- auto-delete partitions older than 1 year
    labels                   = [("l2l_layer", "bronze"), ("l2l_asset", "{{asset_name}}"), ("l2l_env", "prod")]
);
-- Partition expiration eliminates manual cleanup jobs entirely.
-- For re-ingestible Bronze: 30-day expiration is sufficient.
```

**require_partition_filter — Prevent Full Table Scans:**
```sql
-- For Bronze tables > 100GB, enforce partition filter on ALL queries:
ALTER TABLE `project.bronze_dataset.table`
    SET OPTIONS (require_partition_filter = TRUE);
-- Any query WITHOUT WHERE _ingestion_date = ... returns an error.
-- Protects against accidental full-table scans from downstream analysts.
```

**LOAD DATA INTO — Parallel Ingestion via Wildcard URI:**
```sql
-- BQ auto-parallelizes load when URI includes wildcard (always use wildcard):
LOAD DATA OVERWRITE `project.bronze_dataset.table_STAGING`
FROM FILES (
    format = 'PARQUET',
    uris   = ['gs://bucket/orders/2026/03/04/*.parquet']  -- wildcard → auto-parallel
);
-- BQ splits large files internally. Max: 5TB total per LOAD DATA statement.
-- Separate LOAD DATA calls per date-partition to maximize parallelism.
```

**@@script.bytes_processed — Cost Tracking:**
```sql
-- After the MERGE / LOAD DATA, capture bytes for cost attribution:
DECLARE v_bytes INT64;
SET v_bytes = @@script.bytes_processed;

INSERT INTO {{dataset}}.L2L_EXECUTION_LOG
    (ASSET_NAME, LAYER, BATCH_DATE, ROWS_LOADED, BYTES_PROCESSED, STATUS, EXECUTED_AT)
VALUES
    ('{{asset_name}}', 'BRONZE', p_batch_date, v_rows_loaded, v_bytes, 'SUCCESS', CURRENT_TIMESTAMP());
-- Reference: 1TB on-demand = ~$5 USD. Alert orchestrator if bytes_processed > 10TB per run.
```
