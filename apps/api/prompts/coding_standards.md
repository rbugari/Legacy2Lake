# L2L Coding Standards — Platform-Agnostic (All Cartridges)

## 1. Supported Target Platforms

Agent C selects the cartridge based on `config['target_platform']`. Each platform has a complete cartridge set for all four Medallion layers.

| `target_platform` key | Platform | Language / Runtime | Cartridge Prefix |
|---|---|---|---|
| `databricks` | Databricks Lakehouse | PySpark / Delta Lake | `cartridge_databricks_` |
| `pyspark` | Generic PySpark (on-prem / EMR / ADLS) | PySpark | `cartridge_pyspark_` |
| `cloudera` | Cloudera CDH/CDP | PySpark + Hive/Impala | `cartridge_cloudera_` |
| `microsoft_fabric` | Microsoft Fabric (OneLake) | PySpark / Spark Notebook | `cartridge_microsoft_fabric_` |
| `snowflake_snowpark` | Snowflake (Python Snowpark) | Python + Snowpark | `cartridge_snowflake_snowpark_` |
| `snowflake_sql` | Snowflake (Native SQL Procedures) | SQL Scripting | `cartridge_snowflake_sql_` |
| `bigquery` | Google BigQuery | BigQuery Standard SQL Scripting | `cartridge_bigquery_` |

## 2. Universal Rules (Apply to ALL Platforms)

### 2.1 L2L Trace Header (CRITICAL — EVERY generated file)
Every generated asset MUST begin with a modernization trace block:

```
# L2L MODERNIZATION TRACE: {layer} Layer - {asset_name}
# Source: {source_tech} Asset '{source_asset_name}'
# Target Platform: {platform_label}
# Medallion Layer: {layer}
# Component Type: {component_type}
# Generated At: {timestamp}
# Generated By: L2L Agent-C (Cartridge: {cartridge_key})
```
*(SQL-based cartridges use `-- comment` style; Python-based cartridges use `#`.)*

### 2.2 Zero-Hardcode Policy (ALL PLATFORMS)
- No literal connection strings, project IDs, database names, bucket paths, or credentials in generated code.
- All parameters come from the function/procedure signature: `context['param']` (Python) or `IN p_param` (SQL).

### 2.3 Idempotency (ALL PLATFORMS)
- All writes to Silver and Gold must be idempotent.
- Preferred mechanism: `MERGE INTO` (or platform equivalent).
- `OVERWRITE` / `TRUNCATE + INSERT` is acceptable only for Bronze (raw) or Aggregate Gold when explicitly documented as full-refresh.

### 2.4 Data Integrity — NULL Safety (ALL PLATFORMS)
- All Lookups / dimension JOINs must handle misses — never allow NULL surrogate keys in Fact tables.
- Use `COALESCE(dim.SK, -1)` (integer SK) or `COALESCE(dim.SK, 'UNKNOWN')` (hash SK) as the unknown member.

### 2.5 High-Fidelity Casting (ALL PLATFORMS)
- Every column cast must explicitly match the Destination DDL type.
- Do not rely on engine type inference.

| Logical Type | Databricks / PySpark | Snowflake | BigQuery | MS Fabric |
|---|---|---|---|---|
| Integer | `LongType()` | `NUMBER(18,0)` | `INT64` | `bigint` |
| Decimal(18,4) | `DecimalType(18,4)` | `NUMBER(18,4)` | `NUMERIC(18,4)` | `decimal(18,4)` |
| String | `StringType()` | `VARCHAR` | `STRING` | `varchar(4000)` |
| Timestamp | `TimestampType()` | `TIMESTAMP_NTZ` | `TIMESTAMP` | `datetime2` |
| Boolean | `BooleanType()` | `BOOLEAN` | `BOOL` | `bit` |
| Date | `DateType()` | `DATE` | `DATE` | `date` |

### 2.6 Load Strategy Awareness (ALL PLATFORMS)
- **INCREMENTAL**: Watermark-based filtering on `batch_date` / `modified_date`. Never full-scan source.
- **SCD_2**: Mandatory `VALID_FROM`, `VALID_UNTIL`, `IS_CURRENT`, `RECORD_VERSION`. Two-step MERGE.
- **FULL / OVERWRITE**: Bronze raw only, or Aggregate Gold with explicit `p_load_mode = 'OVERWRITE'` guard.

### 2.7 PII Masking (ALL PLATFORMS)
If the asset config flags PII columns, apply platform-native masking in Silver layer:

| Platform | Masking Function |
|---|---|
| Databricks / PySpark / Cloudera / Fabric | `F.sha2(F.col(col), 256)` or `F.lit('REDACTED')` |
| Snowflake Snowpark | `hashlib.sha256(val.encode()).hexdigest()` |
| Snowflake SQL | `SHA2(col, 256)` |
| BigQuery | `TO_HEX(SHA256(col))` |

### 2.8 Error Handling (ALL PLATFORMS)
- Python (PySpark / Snowpark): `try/except Exception as e: ... raise`
- SQL (Snowflake / BigQuery): `EXCEPTION WHEN ERROR THEN ... RAISE`
- On error: log to the platform's execution log table and re-raise.

## 3. Platform Execution Entry Points

| Platform Group | Function / Procedure Signature |
|---|---|
| Databricks, PySpark, Cloudera, Fabric | `def execute_task(spark: SparkSession, config: dict) -> bool` |
| Snowflake Snowpark | `def execute_task(session: snowflake.snowpark.Session, config: dict) -> bool` |
| Snowflake SQL | `CREATE OR REPLACE PROCEDURE dataset.SP_{LAYER}_{ASSET}(...)` |
| BigQuery SQL | `CREATE OR REPLACE PROCEDURE dataset.SP_{LAYER}_{ASSET}(IN p_project STRING, ...)` |

## 4. Medallion Layer Rules (Platform-Agnostic)

### Bronze Layer
- Raw ingestion — preserve source structure.
- Add audit columns: `_ingestion_timestamp`, `_ingestion_date`, `_source_file`, `_record_hash`.
- Hash per platform: `F.sha2(concat_ws(...), 256)` (PySpark) | `SHA2(...)` (Snowflake SQL) | `TO_HEX(MD5(...))` (BigQuery).
- No business transformations.

### Silver Layer
- Deduplication mandatory: `QUALIFY ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...) = 1`.
- Data quality flags — non-blocking.
- SCD Type 2 (if enabled): `VALID_FROM`, `VALID_UNTIL`, `IS_CURRENT`, `RECORD_VERSION`.
- Two-step MERGE: expire changed actives → insert new versions.

### Gold Layer
- Dispatch by `model_type`: `DIMENSION` | `FACT` | `AGGREGATE`.
- DIMENSION: hash SK + SCD Type 2.
- FACT: SK resolution from dim JOINs + measure computation.
- AGGREGATE: atomic full-overwrite (CTAS or equivalent).

### Direct Layer
- Faithful 1:1 logical translation — no medallion columns added.
- CTE chain: `base → derived → filtered → grouped` as needed.
- Load modes: OVERWRITE | APPEND | MERGE (inferred from source logic).

## 5. Code Quality Minimum Bar
- All generated procedures/functions must be complete and production-ready. Use enough structure and detail for the target artifact; stubs are forbidden.
- Comment every major section: `-- [EXTRACT]`, `-- [TRANSFORM]`, `-- [LOAD]` (or `# EXTRACT`, `# TRANSFORM`, `# LOAD` in Python).
- No magic numbers — business rules in parameters or named constants.
- Column names: `UPPER_SNAKE_CASE` for SQL targets; `snake_case` for Python DataFrames.
- Table aliases: short and meaningful (`f` = fact source, `d1` = dim1, `t` = target, `s` = source).

For `direct` translations and concise SQL targets, prioritize faithful and maintainable output over arbitrary line count expansion.
