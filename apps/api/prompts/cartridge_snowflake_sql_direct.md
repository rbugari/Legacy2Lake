### 2. DIRECT LAYER PHILOSOPHY

**Core Principle: Faithful 1:1 Logical Equivalence in Snowflake SQL**

This cartridge produces a `CREATE OR REPLACE PROCEDURE` that is a **faithful structural mirror** of the original stored procedure, SSIS logic, or SQL job — rewritten using Snowflake SQL syntax.

**What Direct MUST preserve:**
- All WHERE predicates → Snowflake SQL `WHERE` clauses
- Column derivations (CASE / IIF / computed columns) → `CASE WHEN ... END` in CTEs
- Reference joins (Lookup) → `LEFT JOIN` / `INNER JOIN`
- Row routing/branching → `WHERE` filters per output target
- Aggregations → `GROUP BY ... HAVING`
- Row-level calculations → inline expressions in `SELECT`
- Upsert logic (if source had it) → `MERGE INTO`

**What Direct MUST NOT add:**
- No Bronze audit columns (`_INGESTION_TIMESTAMP`, `_RECORD_HASH`)
- No Silver SCD columns (`VALID_FROM`, `IS_CURRENT`)
- No Gold surrogate keys (SHA2)
- No medallion-specific enrichment of any kind

**⚠️ CRITICAL: This cartridge generates SQL Stored Procedures, NOT Python/Snowpark.**

### 4. PROCEDURE STRUCTURE

```sql

    P_DATABASE      STRING,

    P_TARGET_TABLE  STRING,
    P_LOAD_MODE     STRING,
    P_BUSINESS_KEYS STRING,
    P_BATCH_DATE    DATE

RETURNS VARIANT
LANGUAGE SQL
EXECUTE AS CALLER
AS
$$
DECLARE
    v_source_full   STRING  DEFAULT P_DATABASE || '.' || P_SCHEMA || '.' || P_SOURCE_TABLE;
    v_target_full   STRING  DEFAULT P_DATABASE || '.' || P_SCHEMA || '.' || P_TARGET_TABLE;
    v_rows_out      INTEGER DEFAULT 0;
    v_error_msg     STRING;
BEGIN

    -- [EXTRACT + TRANSFORM] CTE-based (Section 5)
    -- [LOAD] OVERWRITE / APPEND / MERGE (Section 6)
    -- [RETURN]

    v_rows_out := SQLROWCOUNT;

    RETURN OBJECT_CONSTRUCT(
        'status',       'SUCCESS',
        'target_table', v_target_full,
        'rows_written', v_rows_out,
        'load_mode',    P_LOAD_MODE

EXCEPTION
    WHEN OTHER THEN
        v_error_msg := SQLERRM;
        RETURN OBJECT_CONSTRUCT('status', 'ERROR', 'message', v_error_msg);

```

### 5. DIRECT TRANSFORMATION PATTERNS (CTE-Based)

All transformations live inside a **CTE chain** preceding the final INSERT/MERGE. This mirrors the way SSIS data flows or staging procedures were structured.

**A. Column Derivation (Derived Column / Computed Columns)**
```sql
-- Inside EXECUTE IMMEDIATE CTE block:
WITH
base AS (
    SELECT *
    FROM {v_source_full}
    WHERE LOAD_DATE >= '{P_BATCH_DATE}'
),
derived AS (
    SELECT
        BUSINESS_KEY_1,
        BUSINESS_KEY_2,
        UPPER(TRIM(NAME))                       AS NAME,
        CONCAT_WS(' ', FIRST_NAME, LAST_NAME)  AS FULL_NAME,
        ROUND(AMOUNT * FX_RATE, 4)             AS AMOUNT_USD,
        DATE_TRUNC('MONTH', TRANSACTION_DATE)  AS PERIOD_MONTH,
        YEAR(TRANSACTION_DATE)                 AS TRANSACTION_YEAR,
        IFF(AMOUNT > 0, TRUE, FALSE)           AS IS_POSITIVE_AMOUNT
    FROM base
)
```

**B. Conditional Logic (CASE WHEN — replaces SSIS Conditional Split / T-SQL IIF)**
```sql
-- Snowflake has both CASE WHEN and IFF (binary shorthand)
filtered AS (
    SELECT
        *,
        CASE
            WHEN CATEGORY_CODE = 'A' THEN 'Premium'
            WHEN CATEGORY_CODE = 'B' THEN 'Standard'
            WHEN CATEGORY_CODE = 'C' THEN 'Economy'
            ELSE 'Unknown'
        END                             AS CATEGORY_LABEL,
        IFF(STATUS = 'ACT', TRUE, FALSE) AS IS_ACTIVE
    FROM derived
)
```

**C. Reference Lookup (SSIS Lookup / T-SQL JOIN)**
```sql
WITH_LOOKUP AS (
    SELECT
        f.*,
        r.LOOKUP_VALUE      AS RESOLVED_LABEL,
        r.CATEGORY_CODE     AS RESOLVED_CATEGORY
    FROM filtered f
    LEFT JOIN {P_DATABASE}.{P_SCHEMA}.{lookup_table_param} r
        ON f.LOOKUP_KEY = r.LOOKUP_KEY
)
```

**D. Row Routing / Multicast (SSIS Conditional Split → multiple targets)**
```sql
-- Route valid records to main target
-- Route invalid records to error table
-- Both use the SAME CTE chain with different WHERE filters

-- Target 1: valid records
INSERT INTO {v_target_full}
SELECT * FROM WITH_LOOKUP
WHERE IS_COMPLETE_RECORD = TRUE;

-- Target 2: error/quarantine table
INSERT INTO {P_DATABASE}.{P_SCHEMA}.{P_TARGET_TABLE}_ERRORS
SELECT *, CURRENT_TIMESTAMP() AS QUARANTINE_TS
FROM WITH_LOOKUP
WHERE IS_COMPLETE_RECORD = FALSE;
```

**E. Aggregation (SQL GROUP BY replaces SSIS Aggregate)**
```sql
grouped AS (
    SELECT
        DIMENSION_KEY,
        DATE_TRUNC('MONTH', TRANSACTION_DATE)   AS PERIOD_MONTH,
        COUNT(*)                                AS TRANSACTION_COUNT,
        SUM(AMOUNT_USD)                         AS TOTAL_AMOUNT,
        AVG(AMOUNT_USD)                         AS AVG_AMOUNT
    FROM WITH_LOOKUP
    GROUP BY 1, 2
    HAVING COUNT(*) > 0
)
```

### 6. LOAD PATTERNS

**OVERWRITE (full replacement — default for Direct):**
```sql
EXECUTE IMMEDIATE '
    CREATE OR REPLACE TABLE ' || v_target_full || ' AS
    WITH
    base     AS (SELECT * FROM ' || v_source_full || ' WHERE LOAD_DATE >= ''' || P_BATCH_DATE::STRING || '''),
    derived  AS (SELECT ..., CASE ... END AS COL FROM base),
    filtered AS (SELECT *, IFF(...) AS IS_ACTIVE FROM derived)
    SELECT * FROM filtered
';
```

**APPEND (incremental — preserves existing rows):**
```sql
EXECUTE IMMEDIATE '
    INSERT INTO ' || v_target_full || '
    WITH
    base     AS (SELECT * FROM ' || v_source_full || ' WHERE LOAD_DATE >= ''' || P_BATCH_DATE::STRING || '''),
    derived  AS (SELECT ... FROM base)
    SELECT * FROM derived
    WHERE NOT EXISTS (
        SELECT 1 FROM ' || v_target_full || ' t
        WHERE t.BUSINESS_KEY_1 = derived.BUSINESS_KEY_1
    )
';
```

**MERGE (upsert — when source had explicit upsert/update logic):**
```sql
EXECUTE IMMEDIATE '
    MERGE INTO ' || v_target_full || ' t
    USING (
        WITH
        base    AS (SELECT * FROM ' || v_source_full || '),
        derived AS (SELECT *, CASE ... END AS COL FROM base)
        SELECT * FROM derived
    ) s
    ON t.BUSINESS_KEY_1 = s.BUSINESS_KEY_1
       AND t.BUSINESS_KEY_2 = s.BUSINESS_KEY_2
    WHEN MATCHED THEN UPDATE SET
        t.ATTRIBUTE_A = s.ATTRIBUTE_A,
        t.AMOUNT      = s.AMOUNT
    WHEN NOT MATCHED THEN INSERT
        (BUSINESS_KEY_1, BUSINESS_KEY_2, ATTRIBUTE_A, AMOUNT)
    VALUES
        (s.BUSINESS_KEY_1, s.BUSINESS_KEY_2, s.ATTRIBUTE_A, s.AMOUNT)
';
```

### 7. SNOWFLAKE SQL FUNCTION EQUIVALENCE TABLE

| Legacy / T-SQL | Snowflake SQL Equivalent |
|---|---|
| `ISNULL(col, default)` | `COALESCE(col, default)` — or `IFF(col IS NULL, default, col)` |
| `GETDATE()` | `CURRENT_TIMESTAMP()` |
| `CONVERT(INT, col)` | `col::INTEGER` or `TRY_CAST(col AS INTEGER)` |
| `CHARINDEX(str, col)` | `CHARINDEX(str, col)` — identical in Snowflake |
| `SUBSTRING(col, 1, 5)` | `SUBSTRING(col, 1, 5)` or `LEFT(col, 5)` |
| `LEN(col)` | `LENGTH(col)` |
| `DATEADD(day, n, col)` | `DATEADD(DAY, n, col)` — Snowflake: type as string literal |
| `DATEDIFF(day, d1, d2)` | `DATEDIFF(DAY, d1, d2)` |
| `CAST(col AS NVARCHAR)` | `col::STRING` |
| `IIF(cond, a, b)` | `IFF(cond, a, b)` |
| `NEWID()` | `UUID_STRING()` |
| `TOP n` | `LIMIT n` |
| `NOLOCK hint` | Not needed — Snowflake MVCC, no locking |
| `WITH (NOLOCK)` | Remove — Snowflake doesn't lock for reads |
| `@@ROWCOUNT` | `SQLROWCOUNT` (inside SP) |
| `PRINT 'msg'` | No equivalent — use INSERT into log table or RETURN metadata |
| `SET NOCOUNT ON` | Not needed in Snowflake |
| `BEGIN TRAN / COMMIT` | `BEGIN TRANSACTION / COMMIT` (same semantics) |
| `TRY/CATCH` | `EXCEPTION WHEN OTHER THEN` |
| `EXEC sp_name(params)` | `CALL sp_name(params)` |
| `OBJECT_ID('table')` | `INFORMATION_SCHEMA.TABLES` query |
| Oracle `ROWNUM` | `ROW_NUMBER() OVER (ORDER BY 1)` |
| Oracle `NVL(col, v)` | `COALESCE(col, v)` |
| Oracle `DECODE(col, ...)` | `CASE WHEN ... END` |
| Oracle `SYSDATE` | `CURRENT_DATE()` / `CURRENT_TIMESTAMP()` |
| Oracle `TO_DATE(str, fmt)` | `TO_DATE(str, fmt)` — identical |

### 8. SSIS FLOW → SNOWFLAKE SQL MAPPING

| SSIS Component | Snowflake SQL Equivalent |
|---|---|
| OLE DB Source | `SELECT * FROM {source}` (in CTE) |
| OLE DB Destination | `INSERT INTO {target}` / `MERGE INTO` / `CREATE OR REPLACE TABLE ... AS` |
| Derived Column | `expr AS COL_NAME` in SELECT |
| Conditional Split | CTE + separate INSERT per condition (WHERE filter) |
| Lookup (Full Cache) | `LEFT JOIN {lookup_table} ON key = key` |
| Lookup (No Cache) | `LEFT JOIN {lookup_table} ON key = key` (Snowflake optimizes) |
| Aggregate | `GROUP BY ... HAVING ...` |
| Sort | `ORDER BY col ASC/DESC` — only in final SELECT if ordered output needed |
| Merge Join | `JOIN` — Snowflake optimizer handles sort internally |
| Union All | `UNION ALL` |
| Multicast | Multiple INSERT statements from same CTE |
| Data Conversion | `col::TARGET_TYPE` or `CAST(col AS TARGET_TYPE)` |
| Row Count | `SQLROWCOUNT` after last DML |
| Execute SQL Task (pre-DML) | Separate `EXECUTE IMMEDIATE` block at top of SP |
| Execute SQL Task (post-DML) | Separate `EXECUTE IMMEDIATE` block at end of SP |

### 9. EXECUTE IMMEDIATE PATTERN FOR DYNAMIC SQL

When table/column names must be dynamic (from SP parameters):
```sql
-- Build SQL string using parameter concatenation
LET v_sql STRING DEFAULT '
    INSERT INTO ' || v_target_full || '
    WITH base AS (
        SELECT * FROM ' || v_source_full || '
        WHERE LOAD_DATE >= ''' || P_BATCH_DATE::STRING || '''
    )
    SELECT
        BUSINESS_KEY,
        UPPER(TRIM(NAME)) AS NAME,
        AMOUNT::NUMBER(18,4) AS AMOUNT
    FROM base
';

-- Execute the dynamically built SQL
EXECUTE IMMEDIATE v_sql;

-- Capture row count IMMEDIATELY after execution
v_rows_out := SQLROWCOUNT;
```

### 10. TRANSACTION CONTROL (For Multi-Step Direct SPs)

```sql
-- When Direct SP has multiple DML operations that must be atomic:
BEGIN TRANSACTION;

    EXECUTE IMMEDIATE 'TRUNCATE TABLE ' || v_target_full;
    EXECUTE IMMEDIATE 'INSERT INTO ' || v_target_full || ' ...';

    -- Validate
    LET v_rows INTEGER;
    SELECT COUNT(*) INTO v_rows FROM IDENTIFIER(v_target_full);

    IF (v_rows = 0) THEN
        ROLLBACK;
        RETURN OBJECT_CONSTRUCT('status', 'ERROR', 'message', 'No rows written — rolled back');
    END IF;

COMMIT;
```

### 12. SNOWFLAKE NATIVE OPTIMIZATION HINTS

**QUERY_TAG — Cost Attribution (MANDATORY):**
```sql
-- Add at the very START of procedure body:
ALTER SESSION SET QUERY_TAG = 'L2L|DIRECT|{{asset_name}}';
-- Cost attribution: SELECT * FROM TABLE(INFORMATION_SCHEMA.QUERY_HISTORY())
--   WHERE QUERY_TAG LIKE 'L2L|DIRECT|%';
```

**Result Cache — Direct Queries:**
```sql
-- BQ result cache (24h TTL) applies when:
-- ✅ No volatile functions in SELECT list (CURRENT_TIMESTAMP, CURRENT_DATE, UUID, RANDOM)
-- ✅ Source table data unchanged between two identical queries
-- BAD  (breaks cache): SELECT CURRENT_TIMESTAMP() AS LOAD_TS, col1 FROM source
-- GOOD (cacheable):    SELECT col1, col2 FROM source WHERE load_date = :P_BATCH_DATE
-- Tip: always push volatile values to WHERE / HAVING, keep SELECT deterministic.
```

**TRANSIENT Staging Tables:**
```sql
-- If Direct uses intermediate staging (e.g., row routing to multiple targets):
CREATE OR REPLACE TRANSIENT TABLE {{database}}.{{schema}}.DIRECT_{{asset_name}}_WORK AS
    SELECT ...;
-- TRANSIENT → no Fail-Safe overhead. Staging data is always regenerable.
```

**Column Data Masking — PII in Direct Loads (run once as DDL, outside SP):**
```sql
CREATE OR REPLACE MASKING POLICY {{database}}.SECURITY.MP_PII_MASK
    AS (val STRING) RETURNS STRING ->
    CASE
        WHEN CURRENT_ROLE() IN ('DATA_ENGINEER', 'ADMIN') THEN val
        ELSE SHA2(val, 256)
    END;

-- Apply to target table PII column:
ALTER TABLE {{database}}.{{schema}}.{{target_table}}
    MODIFY COLUMN EMAIL_COL SET MASKING POLICY {{database}}.SECURITY.MP_PII_MASK;
```

**Row Access Policy — Multi-Tenant Direct Loads:**
```sql
-- For multi-tenant Direct loads where different roles see different rows:
CREATE OR REPLACE ROW ACCESS POLICY {{database}}.SECURITY.RAP_TENANT
    AS (tenant_col STRING) RETURNS BOOLEAN ->
    tenant_col = CURRENT_ROLE() OR CURRENT_ROLE() IN ('ADMIN', 'DATA_ENGINEER');

ALTER TABLE {{database}}.{{schema}}.{{target_table}}
    ADD ROW ACCESS POLICY {{database}}.SECURITY.RAP_TENANT ON (TENANT_ID);
```
