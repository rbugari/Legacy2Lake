Deployment Guide

Prerequisites

  • {{ project.target_tech or 'Target platform' }} environment configured and accessible
  • Database credentials with CREATE, ALTER, and INSERT permissions
  • Network access to target data warehouse/lakehouse
  • Orchestration platform (Airflow, dbt Cloud, etc.) for ETL scheduling
  • Version control system (Git) for artifact management

Deployment Steps

  1. Review Generated Artifacts
    Download all files from the Handover stage. Organize into /ddl and /etl folders.
  2. Execute DDL Scripts
    Run DDL scripts in dependency order to create schemas, tables, and views in {{ project.target_tech or 'target platform' }}.
  3. Deploy ETL Scripts
    Upload ETL scripts to your orchestration platform. Configure connections and environment variables.
  4. Configure Environment Variables
    Set database credentials, warehouse names, schema paths, and any platform-specific parameters.
  5. Run Initial Data Load (FULL)
    Execute FULL load strategies first to populate base tables with historical data.
  6. Validate Data Quality
    Compare row counts, data types, and sample records between source and target systems.
  7. Schedule Incremental Loads
    Configure INCREMENTAL load jobs to run on a regular schedule (hourly, daily, etc.).
  8. Monitor and Optimize
    Set up monitoring dashboards, alerts, and performance tuning as needed.

Rollback Procedure

In case of critical issues during deployment:

  1. Stop all running ETL jobs immediately
  2. Backup newly created tables (if data was loaded)
  3. Drop tables created by DDL scripts (use DROP TABLE IF EXISTS)
  4. Restore from legacy system if business continuity is affected
  5. Contact migration team lead for troubleshooting support
