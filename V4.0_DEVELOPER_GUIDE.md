## 🎯 Overview

v4.0 "Zero-Hardcode Core" eliminates ALL hardcoded templates from the codebase and replaces them with **dynamic, database-driven prompts**. This enables:

- ✅ Change prompts without redeploying backend
- ✅ Automatic version history for all prompt changes
- ✅ Field-level forensic analysis (PII detection, quality scoring)
- ✅ Real-time code validation during generation

## 🗄️ Database Changes

### New Tables

#### `utm_prompts` - Dynamic Prompts
```sql
CREATE TABLE utm_prompts (
    prompt_id TEXT PRIMARY KEY,        -- e.g., 'agent_c_bronze_pyspark'
    content TEXT NOT NULL,             -- Prompt template with {{variables}}
    tech_stack TEXT,                   -- 'pyspark', 'snowflake', 'dbt', etc.
    pattern_type TEXT,                 -- 'bronze', 'silver', 'gold'
    agent_id TEXT,                     -- 'agent-c', 'agent-a', etc.
    is_active BOOLEAN DEFAULT true,
    metadata JSONB,
    created_at TIMESTAMPTZ,
    updated_at TIMESTAMPTZ
);
```

#### `utm_prompts_history` - Automatic Versioning
```sql
CREATE TABLE utm_prompts_history (
    history_id UUID PRIMARY KEY,
    prompt_id TEXT NOT NULL,
    content TEXT NOT NULL,            -- Snapshot of previous content
    changed_by UUID,
    changed_at TIMESTAMPTZ,
    previous_content_hash TEXT
);
```

#### `utm_column_profiles` - Field-Level Analysis
```sql
CREATE TABLE utm_column_profiles (
    profile_id UUID PRIMARY KEY,
    project_id UUID NOT NULL,
    object_name TEXT NOT NULL,
    column_name TEXT NOT NULL,
    inferred_type TEXT,               -- 'STRING', 'INTEGER', 'DECIMAL', etc.
    nullability_score FLOAT,          -- 0.0 to 1.0
    quality_score INTEGER,            -- 0 to 100
    semantic_tags TEXT[],             -- ['PII', 'EMAIL', 'PHONE']
    pii_detected BOOLEAN,
    statistical_profile JSONB,
    recommendations JSONB
);
```

#### `utm_generation_outcomes` - Learning Data
```sql
CREATE TABLE utm_generation_outcomes (
    outcome_id UUID PRIMARY KEY,
    project_id UUID NOT NULL,
    agent_id TEXT NOT NULL,
    generated_code TEXT,
    validation_passed BOOLEAN,
    quality_score INTEGER,
    tokens_used INTEGER,
    model_used TEXT,
    duration_ms INTEGER
);
```

## 🎨 Prompt Template Syntax

### Variables

```python
# Simple variable
"Table name: {{table_name}}"

# Nested access
"Source: {{schema.table_name}}"

# With filters
"Schema: {{schema | json}}"
"Name: {{table_name | upper}}"
```

### Supported Filters

- `json` - Convert to JSON string
- `upper` - Convert to uppercase
- `lower` - Convert to lowercase
- `trim` - Remove whitespace
- `lines` - Join list with newlines

### Example Prompt Template

```python
# BRONZE LAYER INGESTION
# Source: {{schema.source_name}}
# Target: {{target_table_full}}

from pyspark.sql import SparkSession

# Configuration
CATALOG = "{{params.catalog_name}}"
BRONZE_SCHEMA = "{{params.bronze_schema}}"
TARGET_TABLE = "{{target_table_name}}"

# Initialize Spark
spark = SparkSession.builder.appName("bronze_{{schema.table_name}}").getOrCreate()

# Select columns
source_columns = {{columns_formatted}}

df_bronze = df_source.select(*source_columns)

print(f"✅ Bronze ingestion complete: {CATALOG}.{BRONZE_SCHEMA}.{TARGET_TABLE}")
```

## 🐛 Troubleshooting

### Issue: Prompts not loading

**Solution:**
```python
# Clear cache
from apps.api.services.prompts.prompt_service import PromptService
service = PromptService()
service.clear_cache()

# Or via API
curl -X POST http://localhost:8000/api/v1/prompts/cache/clear
```

### Issue: Template variables not substituting

**Check your template syntax:**
```python
# ✅ Correct
"Table: {{table_name}}"

# ❌ Wrong
"Table: {table_name}"    # Missing double braces
"Table: ${table_name}"   # Wrong syntax
```

### Issue: PII detection not working

**Check column values:**
```python
# Ensure you're passing actual sample values
values = ["user@test.com", "admin@example.com"]  # ✅ Good
values = ["email"]  # ❌ Bad - generic name, not actual values
```

## 🎨 Sprint 14: Component Unification (February 2026)

**Status:** ✅ COMPLETED - February 19, 2026  
**Goal:** Replace all legacy stage-specific components with unified, reusable components

### Overview

Sprint 14 componentization eliminates duplicate implementations across stages (Discovery, Triage, Drafting, etc.) by creating standardized, enhanced components with consistent UX and better maintainability.

### 🔄 Unified Components Created

#### 1. **UnifiedLogViewer** ✅

**Purpose:** Single log viewer implementation for all stages

**Features:**
- ✅ Two variants: `side-panel` (in sidebar) and `embedded` (in main content)
- ✅ Auto-loads historical logs when tab opened
- ✅ Real-time streaming during active processes
- ✅ Contextual empty states based on mode/state
- ✅ Manual refresh button
- ✅ Auto-scroll to latest logs
- ✅ "Enhanced" badge for visual consistency

**Usage:**
```tsx
import UnifiedLogViewer from "@/components/UnifiedLogViewer";

// Embedded in main content area
<UnifiedLogViewer
  logs={logs}
  isRunning={isRunning}
  variant="embedded"
  onRefresh={fetchLogs}
/>

// In side panel
<UnifiedLogViewer
  logs={logs}
  isRunning={isRunning}
  variant="side-panel"
/>
```

**Props:**
```typescript
interface UnifiedLogViewerProps {
  logs: Array<{ timestamp: string; level: string; message: string; agent?: string }>;
  isRunning: boolean;
  variant?: 'side-panel' | 'embedded'; // Default: embedded
  onRefresh?: () => void;
  title?: string;
  height?: string; // CSS height value
}
```

**States Handled:**
- Running process → Shows live logs with auto-scroll
- Historical logs → Shows last execution with refresh button
- Empty state → Contextual message based on variant
- Error state → Red-bordered error messages

**Replaced Components:**
- TriageView custom log section (~80 lines)
- DraftingView custom log viewer (~60 lines)
- Discovery stage log displays

#### 2. **UnifiedFileExplorer** ✅

**Purpose:** Single file explorer implementation for all project file browsing

**Features:**
- ✅ Tree view with collapsible folders
- ✅ Resizable split panels (tree + content viewer)
- ✅ Syntax highlighting for 12+ languages
- ✅ **File type filter** (dropdown in header) - Filter by .py, .sql, .json, etc.
- ✅ **Timestamp display** - Format: `yy-mm-dd hh:mm` (e.g., "26-02-19 14:30")
- ✅ Smart filtering (shows parent folders of matching files)
- ✅ Auto-expand folders to configurable depth
- ✅ Panel state persistence (width, visibility)
- ✅ "Enhanced" badge with blue gradient header
- ✅ Empty state with "Clear filter" button

**Usage:**
```tsx

// Basic usage
<UnifiedFileExplorer 
  projectId={projectId} 
  activeTenantId={activeTenantId}

// Customized
<UnifiedFileExplorer
  projectId={projectId}

  title="Solution Output"
  variant="compact"
  autoExpandDepth={3}
```

**Props:**
```typescript
interface UnifiedFileExplorerProps {
  projectId: string;
  activeTenantId?: string;
  showToolbar?: boolean;        // Default: true
  readOnly?: boolean;           // Default: true
  onFileSelect?: (file: FileNode) => void;
  variant?: 'full' | 'compact'; // Default: 'full'
```

**File Type Filter:**
- Automatically detects all file extensions in project
- Dropdown shows: "All Files", ".py files", ".sql files", etc.
- Filtering happens client-side (instant, no API calls)
- Smart folder handling (keeps folders with matching descendants)
- Clear filter button when no matches found

**Timestamp Display:**
- Always visible (no hover required)
- Format: `26-02-19 14:30` (year-month-day hour:minute)
- Helps identify old vs. recently generated files
- Monospace font for alignment
- Shown in both tree view and file header

**Replaced Components:**
- `FileManagerTab` component (~300 lines - DELETED)

**Syntax Highlighting:**

### 🚀 Integration Guide

#### Adding UnifiedLogViewer to a New Stage

```tsx
// 1. Import component
import UnifiedLogViewer from "../UnifiedLogViewer";

// 2. Add state for logs
const [logs, setLogs] = useState<any[]>([]);
const [isRunning, setIsRunning] = useState(false);

// 3. Create fetch function
const fetchLogs = async () => {
  try {
    const res = await fetchWithAuth(`projects/${projectId}/stage-name/logs`);
    const data = await res.json();
    setLogs(data.logs || []);
  } catch (e) {
    console.error("Failed to load logs", e);
  }
};

// 4. Load logs when section active
useEffect(() => {
  if (activeSection === 'logs') {
    fetchLogs();
  }
}, [activeSection]);

// 5. Render component
{activeSection === 'logs' && (
  <UnifiedLogViewer
    logs={logs}
    isRunning={isRunning}
    variant="embedded"
    onRefresh={fetchLogs}
    title="Stage Name Logs"
  />
)}
```

#### Adding UnifiedFileExplorer to a New Stage

```tsx
// 1. Import component
import UnifiedFileExplorer from "../UnifiedFileExplorer";

// 2. Render component (no state needed!)
{activeSection === 'files' && (
  <UnifiedFileExplorer 
    projectId={projectId} 
    activeTenantId={activeTenantId}
    title="Stage Files"
  />
)}

// That's it! The component handles:
// - File tree loading
// - File content fetching
// - Syntax highlighting
// - Panel resizing
// - Filter management
// - State persistence
```
