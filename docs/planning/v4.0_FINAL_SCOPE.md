## 📋 FINAL SCOPE

### Feature 1: Zero-Hardcode Generation ✅

**QUÉ SÍ:**
- ✅ Eliminar TODOS los templates hardcoded de Python/TypeScript
- ✅ Prompts dinámicos en base de datos
- ✅ Versionado automático (trigger guarda versión anterior - SOLO HISTORIAL)
- ✅ Prompts globales para toda la aplicación

**QUÉ NO (eliminado/simplificado):**
- ❌ Customización por tenant → NO. Los prompts son globales
- ❌ Sistema complejo de versionado → Trigger simple es suficiente
- ❌ UI para cambiar versiones → NO. Solo historial read-only para ADMIN
- ❌ Rollback feature para usuarios → NO. Solo safety net automático
- ❌ Selección de versión activa/inactiva → NO. Auto-trigger solo

**Rationale:**
- Los prompts son para toda la plataforma
- Tenant customiza según su tecnología/necesidades, no los prompts base
- Versionado es SOLO para análisis futuro y seguridad (por si algo se rompe)
- Historial es read-only para ADMIN - usuarios no interactúan con versiones
- Trigger automático = safety net sin overengineering

## 🗄️ Database Schema (Simplified)

```sql
-- Tabla principal de prompts (GLOBAL)
CREATE TABLE utm_prompts (
    prompt_id TEXT PRIMARY KEY,
    content TEXT NOT NULL,
    tech_stack TEXT,
    pattern_type TEXT,
    agent_id TEXT,
    is_active BOOLEAN DEFAULT true,
    created_by UUID,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    metadata JSONB
);

-- Historial automático (trigger) - READ-ONLY para ADMIN
-- IMPORTANTE: Esta tabla es SOLO para análisis y seguridad
-- NO hay UI de rollback - solo ADMIN puede consultar historial
CREATE TABLE utm_prompts_history (
    history_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    prompt_id TEXT NOT NULL,
    content TEXT NOT NULL,
    tech_stack TEXT,
    pattern_type TEXT,
    agent_id TEXT,
    metadata JSONB,
    changed_by UUID,
    changed_at TIMESTAMPTZ DEFAULT NOW()
);

-- Trigger que guarda versión anterior automáticamente (safety net)
-- Los usuarios NO interactúan con esto - es automático
CREATE TRIGGER prompt_version_trigger
    BEFORE UPDATE ON utm_prompts
    FOR EACH ROW
    EXECUTE FUNCTION save_prompt_version();
```

**Key points:**
- ❌ NO hay columna `tenant_id` (prompts globales)
- ❌ NO hay columna `version` con números (trigger simple)
- ✅ Historial se guarda automáticamente al hacer UPDATE
- ✅ Historial es READ-ONLY para ADMIN (análisis y seguridad)
- ❌ NO hay UI para cambiar versiones o hacer rollback
- ❌ Usuarios NO interactúan con versiones - solo ADMIN puede consultar historial
