## ✅ Lo Que SÍ Hacemos

### 0. **Backward Compatibility** ⭐ (LO MÁS IMPORTANTE)

```
Si tenant tiene 1 solo usuario ADMIN:
✅ Login funciona IGUAL que antes
✅ UI se ve IGUAL que antes
✅ Proyectos funcionan IGUAL que antes
✅ No ve botón "Team" (porque está solo)
✅ ZERO cambios visibles

= Para usuarios actuales, v3.9 es TRANSPARENTE
```

**La diferencia solo aparece si OPCIONALMENTE invitan más usuarios.**

### 1. Multi-Usuario Básico (OPCIONAL)
```
MÍNIMO: 1 Tenant = 1 Usuario (como v3.8, funciona igual)
OPCIONAL: 1 Tenant = 2-10 Usuarios (nuevo)
```

### 2. Solo 3 Roles (Súper Simple)

| Rol | Puede Hacer |
|-----|-------------|
| **ADMIN** 🔴 | Todo: invitar, crear, editar, eliminar, ejecutar stages |
| **COLLABORATOR** 🔵 | Crear proyectos, editar, ejecutar stages, descargar reportes |
| **VIEWER** ⚪ | Solo ver proyectos y descargar reportes |

**No más roles.** Esto cubre 95% de casos de uso.

### 3. Todos Ven Todo
- Todos los usuarios del tenant ven TODOS los proyectos
- No hay "compartir proyecto X con usuario Y"
- Simplifica UI y lógica de permisos

### 4. Invitaciones Email Simple
1. ADMIN ingresa email + rol
2. Usuario recibe link
3. Usuario crea password
4. Done

## 💼 Business Value

### Casos de Uso que Cubre

**Caso 1**: ✅ **Usuarios existentes que quieren seguir solos**
- Nada cambia para ellos
- UI idéntica
- Funciona como siempre
- Pueden usar la plataforma exactamente igual

**Caso 2**: ✅ **Consultora con 3-5 analistas** que trabajan en migraciones
- Admin invita al equipo
- Todos ven los mismos proyectos
- Colaboran sin fricción

**Caso 3**: ✅ **Empresa con 1 Admin + 2 developers** que ejecutan stages
- Admin controla quien puede ejecutar
- Developers tienen rol COLLABORATOR

**Caso 4**: ✅ **Cliente que quiere dar acceso read-only** a stakeholders
- Admin invita con rol VIEWER
- Solo pueden ver y descargar reportes

**Caso 5**: ✅ **Equipo disperso** que necesita acceso compartido
- Todos acceden desde donde estén
- Proyectos sincronizados en tiempo real

### Lo Que NO Cubre (y está OK)
- ❌ Equipos mega-grandes (50+ personas) → No es nuestro target
- ❌ Colaboración tipo Google Docs → Para eso existe Slack
- ❌ Workflows complejos con aprobaciones → YAGNI

### Modelos de Consumo (Futuro Post-v4.0)

Ya estamos preparados para pricing tiers:

```sql
-- Field ya existe en utm_tenants (v3.9):
```

**Implementación futura**:
```

STANDARD: $149/mes - 1 ADMIN + 2 COLLABORATORS
PREMIUM:  $499/mes - 1 ADMIN + 9 usuarios any role
```

## 💬 FAQ

**Q: ¿Por qué solo 3 roles?**  
A: Cubre 95% de casos. Más roles = más complejidad sin valor.

**Q: ¿Y si necesitamos compartir 1 proyecto con 1 usuario específico?**  
A: No es el caso de uso común. Si surge, lo agregamos en v4.x.

**Q: ¿Por qué eliminamos comentarios/notificaciones?**  
A: No somos Slack. Los equipos ya tienen herramientas de comunicación.

**Q: ¿Y los modelos S/M/L de consumo?**  
A: El campo `tier` ya existe. Implementaremos lógica de billing post-v4.0.

**Q: ¿Cuándo agregamos features complejas si las necesitamos?**  
A: Post-v4.0, basado en feedback real de usuarios, no suposiciones.
