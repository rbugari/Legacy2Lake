## 🔧 BUGS CORREGIDOS (Esta sesión — Feb 25-27, 2026)

### Bug #1: `utm_tenants.client_id` no existe ✅ FIXED
**Síntoma:** Error 500 en todas las requests cuando Ghost Mode estaba activo  
**Causa:** `get_identity()` en `dependencies.py` consultaba la columna `client_id` en `utm_tenants`, columna eliminada en migración 024 (v3.9).  
**Fix:** `apps/api/routers/dependencies.py` — en el bloque de impersonación, `target_client_id` ahora se toma directamente del header `X-Client-ID` del admin que inicia la sesión, sin consulta adicional a `utm_tenants`.

```python
# ANTES (ROTO)
tenant_res = db.client.table("utm_tenants").select("client_id")\
    .eq("tenant_id", target_user["tenant_id"]).execute()
target_client_id = tenant_res.data[0]["client_id"] if tenant_res.data else "UNKNOWN"

# DESPUÉS (CORRECTO)
target_client_id = x_client_id  # Usa el del header enviado por el admin
```

### Bug #2: Admin page retorna 403 en Ghost Mode ✅ FIXED
**Síntoma:** `/auth/admin/users` y `/auth/tenants` respondían 403 cuando el admin tenía activo el Ghost Mode en el browser.  
**Causa:** `fetchWithAuth` en `auth-client.ts` siempre enviaba `X-Impersonate-User-ID` si estaba en localStorage, incluso desde la página `/admin`. El backend interpretaba al admin como el usuario impersonado, que no tiene role ADMIN.  
**Fix (2 partes):**

1. `apps/web/app/lib/auth-client.ts` — nuevo parámetro `skipImpersonation?: boolean` en `FetchAuthOptions`
2. `apps/web/app/admin/page.tsx` — wrapper local de `fetchWithAuth` que fuerza `skipImpersonation: true` en todas las calls de la página de administración

```typescript
// auth-client.ts
export interface FetchAuthOptions extends RequestInit {
    skipImpersonation?: boolean;
}

// admin/page.tsx (fuera del componente)
const fetchWithAuth = (endpoint: string, options: any = {}) => 
    baseFetchWithAuth(endpoint, { ...options, skipImpersonation: true });
```

### Bug #3: StrategicIntelligenceHub — JSX parsing error ✅ FIXED
**Síntoma:** Error de compilación Turbopack en `StrategicIntelligenceHub.tsx` — template literal JSX mal escapado.  
**Fix:** Corrección del escape en el bloque `<style jsx>`.

### Bug #4: UserManagement — desbordamiento de botones en modal ✅ FIXED
**Síntoma:** Botones del modal "Create/Edit User" salían del área visible.  
**Fix:** Ajuste de layout y padding en `UserManagement.tsx`.

### Bug #5: Dropdown legibility en StrategicIntelligenceHub ✅ FIXED
**Síntoma:** Texto gris sobre fondo gris en los `<select>` del hub.  
**Fix:** `bg-slate-800 text-white` sobre las opciones del dropdown.

## 🏗️ Arquitectura del Rol ADMIN

### Headers de autenticación
| Header | Propósito |
|---|---|
| `X-Tenant-ID` | UUID del tenant del usuario (requerido, validado como UUID v4) |
| `X-User-ID` | UUID del usuario autenticado |
| `X-Client-ID` | UUID del cliente (legacy — mismo valor que tenant_id para tenants nuevos) |
| `X-Role` | Rol del usuario (ADMIN / MANAGER / COLLABORATOR / VIEWER) |
| `X-Impersonate-User-ID` | [Solo Ghost Mode] UUID del usuario a impersonar |

### Ghost Mode flow
```
Admin activa Ghost Mode → localStorage.setItem("x_impersonate_user_id", targetUserId)
↓
fetchWithAuth envía X-Impersonate-User-ID (salvo skipImpersonation=true)
↓
get_identity() detecta admin + impersonate → devuelve identidad del usuario objetivo
↓
SupabasePersistence usa tenant_id del usuario objetivo
↓
list_projects filtra por ese tenant_id
```

### Página de Admin (skipImpersonation)
La página `/admin` usa un wrapper local que fuerza `skipImpersonation: true` — nunca propaga el Ghost Mode hacia sus propias APIs de gestión. Esto garantiza que el admin puede gestionar la plataforma sin importar si hay una sesión fantasma activa.
